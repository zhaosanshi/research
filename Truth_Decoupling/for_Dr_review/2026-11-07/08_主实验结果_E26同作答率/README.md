## 1. 实验怎么做的

- 固定题集上，每种方法先生成候选答案，再按分数只交付 25% / 50% / 75% 的实质回答，其余一律交付"I don't know."；模型自己的拒答不能填额，回答不够就标"不可行"。比较交付集里答对多少。
- 方法：原模型（按承诺分、简单置信、随机三种挑题）；只推 E、只推 C、E+C（DAS 与均值差两种方向）；E、C 配简单置信挑题。"承诺分"是模型对"你知道 / 能答这题吗"首词 Yes 减 No 的分数；"简单置信"是真假判断里 True / False 对数概率差的绝对值、问答里答案的平均对数概率。
- 每档作答率的配置在 192 道调参题上独立选，529 道测试题上报告。分析计划（主对比 = DAS 的 E+C 对 E，12 格 Holm 校正）在测试阶段开始之前提交（`66868ab`，18:27；测试收集 18:42 起）。
- 两点边界：① 问答候选"是不是实质回答"由看过参考答案的语义裁判标注，排序分本身不看参考答案；② TruthfulQA 817 题已全部用过，测试集在前几轮看过，这是"已看过的测试集上的比较"。

## 2. 结果

| 问题 | 结果 | 对论文 |
|---|---|---|
| 相同作答率下，E+C 是否胜过只推 E（主对比） | **否。** 12 格差值 −3 到 +9 题，Holm 校正后 0 格显著 | 对博士原句：消极（但见第 4 节——这还不是赵磊说的那个实验） |
| 只推 C 是否有用 | **配额口径下没有。** 对原模型 12 格全部约等于 0。C 把承诺分整体平移 0.6–1.0 个标准差，排序几乎不变（秩相关 0.96–0.998；交付题目只换 2–16 道） | 对"C 是门槛旋钮"：积极 |
| 推 E 是否有用 | **真假判断上有用**：对原模型（都按承诺分挑题）50% / 75% 两模型都显著（+26 到 +40 题）；E + 简单置信对原模型 + 简单置信，Llama 显著（+40 / +44），Qwen 未过校正。**自由问答上没用** | 真假判断：积极；问答：消极 |
| 承诺分适不适合挑题 | **很差。** E+C 在真假判断 5 个格子里显著输给简单置信挑题；原模型按承诺分挑题，75% 档比随机还差（Qwen −49，校正后显著） | 新发现（首页第二节 6） |
| C 能否调动实际作答 | 同一 C 把"能答"的自报比例从 0.33 推到 0.73；写进答案提示后模型自己弃答只变 ±4–6 个百分点。**但让 C 的 Yes / No 真的决定交付时，交付量从 0 到 164 / 192**（GPT 第 20 轮原生门控，见第 5 节） | 自报与行为分开看；C 作为旋钮可用 |
| GPT 第 18 轮的生成适配（E27）正结果 | 发布版代码复现了数字，但扣除乱码与未结束回答后脆弱、与 DAS 无关；Llama 零效果（力度 3，Claude 定的）；算子即已发表的秩 1 LoReFT | 对 DAS 作为方法：消极；E27 已停 |

**探索性补充：Qwen 带生成适配器的同作答率版本**（报告 `14` 第 5 节）：自然作答率下多答对 40–50 题，对齐作答率后三种适配器都不比原模型好（DAS 起步按原判 +13，扣掉乱码 −2）；叠加 C 也没用。表面提升来自"答得更多"——这是博士"相同作答率"口径的第一个实例。

## 3. 结果核查：负结果不是代码错误

应赵磊要求（11-06 22:00）做的执行级核查，脚本 [`review_checks/e26_independent_recount.py`](../../../claude_gpt_review/from_claude/code/scripts/review_checks/e26_independent_recount.py) 不导入 E26 代码，按同一配额规则从逐题原始记录重算：

| 核查 | 结果 |
|---|---|
| 测试集主表：每个方法、每档作答率的交付答对数 | 244 个格子零差异 |
| 调参集上的冻结选择 | 225 个零差异 |
| C 是否真的写进模型 | 承诺分平均平移 Llama +2.68、Qwen −11.78，与开跑前剂量探测（+2.57、−11.91）一致 |
| E 是否真的写进模型 | 真假判断翻转 Llama 74、Qwen 83 题；问答里 E 每个生成词元写一次，C 在提示末位写一次，回答原文改变 56–114 题 |

GPT 第 20 轮又独立复算了同一批：244 格、225 个选择、1848 个精确检验、2000 次重抽样区间全部一致，并确认 Claude 的启动与分析脚本无误。**结论：E+C ≈ E 不是算错，是配额口径决定的**（C 平移门槛不改排序）。GPT 对这句话的保留意见是"C 不是严格的纯平移"（交付题目换了 2–16 道）——数字成立，不改变结论。

## 4. 这还不是赵磊说的那个实验

E26 的 C 是协方差方向、每模型 1 层按读出相关性选、±1 倍标准差；E 只有 3 个候选层。2×2 验证过的 C（提示对比 / 自报的均值差方向、全层扫描按效果选层、α = 2）从来没有被用进 C+E。按正确口径的重做是 E41（`09`）。

## 5. GPT 第 20、21 轮的复验（11-07）

GPT 在 E26 之后又做了三组工作，结论都没有改变上面的判断：

1. **修正门控提示后重跑整张主表**（"能判真或判假都回答 Yes"；重估 C、重新冻结、完整测试）：真假判断 24 格、问答 24 格，组合对 E 校正后 0 格显著。50% 简单置信筛题下原模型 / E / C / E+C：Llama 417 / 457 / 425 / 453，Qwen 453 / 470 / 449 / 472。
2. **原生门控**（C 的 Yes / No 真的决定交付，七档力度）：C 能把交付量从 0 拉到 164 / 192，但同样数量下答对数低于固定 E + 置信度门槛（Llama 真假判断 K = 192：145 对 152；问答 K = 155：52 对 64）。**这组最有价值**：证明 C 推得动，也证明门控分挑题差。
3. **固定 E、C 放在 E 之前 / 之后两层**：C 力度降到实际写入量的 1–2%，真假判断 48 格 8 正 30 平 10 负（−1 到 +2 题），问答 24 格无显著；GPT 自己发现浅层 C 符号反向、推不动承诺。Claude 的判断：剂量小一个量级、层按深度比例预设、不是验证过的 C，"小幅正差"在判分噪声内（同文换判分缓存就翻 2–3 题）。

GPT 第 20 轮还修了两处判分问题（纯个人拒答被判对；门控把"陈述为假"读成"不会判断"），旧标签不改、新表另列。详见 [`06`](../06_审核记录/README.md) 与 GPT 原文 [第 20 轮](../../../claude_gpt_review/from_gpt/review_20261107_20.md)、[第 21 轮](../../../claude_gpt_review/from_gpt/review_20261107_21.md)。
