## 一句话核心主张
ReFT（Representation Finetuning · 表示微调 · 不改模型权重，只学一个改写内部表示的小算子）：冻结底座，在选定层、选定提示位置上学一个低秩表示编辑 LoReFT（Low-rank Linear Subspace ReFT · 低秩线性子空间表示微调）Φ(h) = h + Rᵀ(Wh + b − Rh)（R 的行两两正交且长度为 1），用对输出序列的教师强制交叉熵训练；参数量比 LoRA 少一个数量级以上，在常识推理、指令跟随、GLUE 上追平或超过 PEFT（parameter-efficient finetuning · 参数高效微调 · 只训练很少的参数来适配任务）强基线，算术推理偏弱（数字见下表）。

## 方法细节
- **出发点是 DAS（Distributed Alignment Search · 分布式对齐搜索 · 学出能换掉高层变量的那个子空间）的交换干预**（§3.1 式 1）：DII（distributed interchange intervention · 分布式交换干预 · 把基础表示在子空间 R 上的分量换成来源表示的分量）DII(h_b, h_s, R) = h_b + Rᵀ(Rh_s − Rh_b)，R 由 DAS 学出。会议版式 1 印成 "b + Rᵀ(…)"，左边的 b 应为 h_b，是排版笔误（arXiv v3 写作 DII(b, s, R) = b + Rᵀ(Rs − Rb)，b 指基础表示）。
- **LoReFT**（§3.2 式 2）：把"来源投影 Rh_s"换成可学习的 Wh + b；可学参数 {R, W, b}，语言模型冻结。原文："This is identical to eq. (1), except we use a learned projected source Rs = Wh + b."
- **DiReFT**（§3.2 式 3）：Φ(h) = h + W2ᵀ(W1h + b)，去掉正交约束和"减 Rh"这一项，作者说它"可看作直接作用在某些位置隐状态上的 LoRA"。**代码命名与论文不一致**：pyreft@dafd099 的 `DireftIntervention` 文档串是 h + Rᵀ(Wh + b) 且保留正交 R（即附录 E 的一个消融），与论文式 3 对应的是 `NodireftIntervention`（examples/loreft/train.py 注释 "remove ortho + direct edit reft"）。
- **训练目标**（式 4）：生成任务 min −Σ_i log p_Φ(y_i | x y_<i)，teacher forcing（教师强制 · 训练时喂正确前文，让模型预测下一个词），对所有输出位置计损失；分类任务另加分类头（式 5–6）。
- **位置与层**（§4.1、Def 3.1–3.2）：一次干预 = ⟨Φ, P, l⟩。原文："We propose learning interventions on a fixed number of p prefix and s suffix positions in the prompt." 同层各位置可 tied / untied（绑定 / 不绑定 · 共用一套参数或各用各的）。最佳配置（arXiv v3 HTML 表 5 / 7 的下划线项，PDF 文本提取会丢下划线）：常识与算术 p7+s7、绑定、秩 8、全部层；指令跟随 p5+s5、绑定、秩 4、第 3/9/18/24 层；GLUE（表 9–12）秩 1、全部层、只用前缀位置。
- **生成出来的词元不干预**：附录 H 说只需改提示位置，额外开销只发生在填初始 KV cache（键值缓存 · 生成时把前文算好的中间量存起来）那一步；§4.1 也写明干预位置数固定、开销不随提示长度增长。代码层面：官方评测脚本 examples/loreft/compute_metrics.py L198–199 传 `"intervene_on_prompt": True`；pyvene（斯坦福的干预工具库）`generate` 文档串写 "Currently, we support basic interventions **in the prompt only**"（intervenable_base.py L2065–2067），解码步的钩子直接返回不做事（L1556–1561）。
- **与其他表示编辑方法的关系**（附录 B）：RED "对每个位置（包括生成词元）都施加"，作者认为它"更应算 adapter"；ActAdd（activation addition · 激活加法 · 把两句对比提示的激活差加到所有位置）；RepE（representation engineering · 表征工程 · 用对比提示做 PCA（主成分分析 · 找方差最大的方向）取方向）的投影算子 h − c·(a·h/‖a‖²)·a "是缩放的一维分布式交换干预，是 LoReFT 的特例"。
- **初始化**：论文没有任何"用探针 / 学好的方向初始化 R"的做法。代码 interventions.py L13–21 `LowRankRotateLayer` 用 `torch.nn.init.orthogonal_` 随机正交初始化，再套 PyTorch 正交参数化（L37–39）；W、b 是 `nn.Linear` 默认初始化（L40–42）。附录 H 测开销时也是"不训练、随机初始化"。
- **参数化消融**（附录 E，沿用 LoReFT 超参即秩 8）：h + Rᵀb（纯加法 steering（引导 · 往残差里加一个方向让输出变）向量）、h + Rᵀ(b − Rh)（把投影钳到常数）、h + Rᵀ(Wh + b)、去正交版 h + W2ᵀ(W1h + b − W2h)。
- **rank-1（秩 1 · 只动一个方向）实验**：GLUE 最终配置全是秩 1；附录 F 用"去掉 Wh、只学 R 和一个标量 b"的输入无关 rank-1 LoReFT，只写最后一个提示位置的残差，测能背多长的文本；附录 A 的示例代码和附录 H 的开销测试也含秩 1。
- **附录 G.2**：rank-4 LoReFT、第 15 层、最后一个提示位置，5 条样例就把 Llama-2-Chat 训成"什么都婉拒"的 GOODY-2 风格（只有定性输出）。
- **训练设置**：AdamW（带权重衰减的 Adam 优化器 · 常用的自适应学习率优化器）、线性学习率；底座以 bf16（bfloat16 · 半精度浮点）载入；单卡 A100 或 RTX 6000。

## 与本方案（E/C 双重分离 + 等覆盖率组合）的关系
- 重叠点：
  1. **生成适配就是 rank-1 LoReFT 的一个参数绑定特例**（代数与逐项对照见下）：底座冻结、单个低秩子空间、对正确答案做教师强制 CE（cross-entropy · 交叉熵 · 让正确答案每个词概率变高的损失）、屏蔽提示标签——全是 ReFT 的核心配方。
  2. 作者团队与 DAS 相同，原文明说 LoReFT "building directly on the distributed alignment search (DAS) method"——"从 DAS 子空间走到用任务损失直接训练表示干预"这一步，ReFT 已经在顶会走过。
- **代数核对（生成适配 ⊂ rank-1 LoReFT）**：适配器 h' = h + α·w·wᵀ(h − c)，‖w‖ = 1（代码 F.normalize）。取 R = wᵀ（1×d；秩 1 时"行正交且单位长"就是单位长度）、W = (1+α)·wᵀ、b = −α·wᵀc，则 Wh + b − Rh = (1+α)wᵀh − α·wᵀc − wᵀh = α·wᵀ(h − c)，所以 Rᵀ(Wh + b − Rh) = α·w·wᵀ(h − c)，**两式完全相等**。附录 B.3 原文本就说"一维缩放投影是 LoReFT 的特例"，生成适配只是再多一个中心 c（落在 b 里）。
- 逐项对照：

| 维度 | ReFT / LoReFT（论文 + 官方代码） | 生成适配（core/qa_generation_adapter.py） | 关系 |
|---|---|---|---|
| 底座 | 冻结 | 冻结 | 相同 |
| 算子 | h + Rᵀ(Wh + b − Rh) | h + α·w·wᵀ(h − c) | 后者 = 前者取 R=wᵀ、W=(1+α)wᵀ、b=−α·wᵀc |
| 单层单组可学参数 | R、W、b；秩 1 时共 2d+1 个 | 只有 w，共 d 个；α、c 固定不学 | 后者是前者的参数绑定子族 |
| 秩 | 1–64（GLUE 最终配置与记忆实验为 1） | 1 | 包含 |
| 写入位置 | 提示前 p 个 + 后 s 个；生成词元不写 | 提示末位 + 每个答案前缀位置（训练与缓存解码同一规则） | **不同**：后者写解码位置，按附录 B.1 的分法更像 RED |
| 位置间参数 | 绑定（全共享）或不绑定（全独立） | w 共享；提示末位、解码位置各用一个固定中心 | 介于两者之间：共享 R、W，b 分组 |
| 层 | 多层（全部层或 4–8 层） | 单层（Qwen 第 34 层） | 子集 |
| 目标 | 输出序列教师强制 CE、屏蔽提示标签；简化例子监督 EOS（end of sequence · 结束符） | 正确答案逐词 CE、按答案长度平均；EOS 默认不训；可选 softplus（平滑版 max(0, x)）排序项（报告中权重 0） | 基本相同（每步一题时按长度平均 = 按词元平均） |
| 初始化 | R 随机正交，W、b 默认 | DAS / 均值差 / 随机单位向量 | **不同**——这是与 DAS 的唯一联系 |
| 优化 | AdamW，学习率约 9e-4，6–12 轮 | Adam，1e-3，3 轮，每步一题，梯度裁剪 1 | 相近 |
| 评测 | 常识、算术、Alpaca-Eval、GLUE | TruthfulQA 自由生成，单裁判 | 不重叠 |

- 冲突点：
  1. **方法新颖性**：若论文把"DAS 初始化的生成适配"写成新方法，审稿人会直接说"这就是参数绑定的 rank-1 LoReFT"。能主张的新东西只剩：写入解码位置、DAS 初始化、在 TruthfulQA 自由生成上的效果。
  2. **初始化不是必要条件**：ReFT 用随机正交初始化 + CE 训练就达到当时最好水平，rank-1 甚至能背 2,048 个词元。这与 GPT 第 18 轮报告里"随机初始化与 DAS 初始化差异不显著"一致——想把适配收益记给 DAS（进而支撑 N3），需要额外证据。
  3. **算子容量很大**：rank-1 能背书说明这个算子可以学走"答题风格"（更少弃答、更长或固定格式的回答），不一定是"更真实"。TruthfulQA 上的提升要拆开看：弃答→正确、错误→正确、正确→错误各多少，以及回答长度与格式的变化。
- 可借用点：
  1. **位置消融**（最该先做）：同一 w 训练预算下比较"只写提示末位"（ReFT 原配方，与 `make_last_position_supervised_chat_data_module` 一致）与"提示末位 + 全部解码位置"。这能直接回答收益是否来自解码位置写入，以及乱码 / 不收尾是否由解码位置写入引起。附录 D.2 的经验是"只改一个位置总不如改多个提示位置"，可再加"提示末尾多个位置"一档。注：ReFT 仓库 TruthfulQA+DPO 教程唯一展示的输出开头也冒出一个乱词（"Luxemberey"），说明这类训练出来的表示干预在问答上同样可能产生乱码。
  2. **参数绑定对照**：在同层同位置加一个"自由 rank-1 LoReFT（W、b 不绑定）"和 pyreft 现成的 `ConsreftIntervention`（h+Rᵀ(b−Rh)）、`LobireftIntervention`（h+Rᵀb），判断"绑定成放大"是帮忙还是限制。
  3. 附录 E 的参数化消融表可以直接套到 E 方向：加法 / 钳制 / 放大三种写法同预算比较。
  4. 只在开发集调参、种子数写清的做法；但不要照抄 pyreft 简化数据模块的分词方式——它按"提示单独分词的长度"屏蔽标签，没有核对整句分词的前缀是否一致（dataset.py L509–515），我们项目以前就遇到过后缀重分词问题。
- 明确差别（我们还能声称什么是新的）：
  1. ReFT 没有 E / C 两条方向、没有判别力测量、没有弃答与等覆盖率——N1、N2 完全空位。
  2. ReFT 不比较 DAS 与均值差估计器——N3 空位。
  3. 生成适配可以诚实地写成"参数绑定的 rank-1 LoReFT 式算子，写入全部答案预测位置，以 DAS 方向初始化"，并引 ReFT 为算子与目标的来源；不能声称算子或训练目标是新的。

## 对三条主张的威胁等级
| 主张 | 威胁 | 理由 |
|---|---|---|
| N1 双重分离 | 无 | 只有单一任务干预，没有两条方向，也没有"判别力 vs 作答率"的分离测量。 |
| N2 等覆盖率组合 | 无 | 没有选择性作答、弃答或覆盖率；附录 G.2 能训出"全拒答"，但与按题选择作答无关。 |
| N3 DAS 胜均值差 | 低 | 不比较估计器；但"随机初始化 + CE 训练就够"使得**拿生成适配的结果支撑 N3** 站不住，若论文那样用，威胁升到中。 |

## 值得引用的原句（≤3 句，标注 section/页）
1. "LoReFT is a parametrisation of ReFT that intervenes on hidden representations in the linear subspace spanned by a low-rank projection matrix, building directly on the distributed alignment search (DAS) method of Geiger et al. [2023] and Wu et al. [2023]." （§1, p.1–2）
2. "The first two of these are similar to activation addition, while the latter is a scaled one-dimensional distributed interchange intervention that is a special case of LoReFT." （附录 B.3, p.20）
3. "On the other hand, we empirically show that LoReFT may only need to intervene on the prompt tokens to achieve good performance, which significantly reduces the overhead due to the fact that we only spend extra time on inference when populating the initial key-value cache." （附录 H, p.38）
