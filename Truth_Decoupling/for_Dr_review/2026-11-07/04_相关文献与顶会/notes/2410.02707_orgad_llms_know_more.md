# 2410.02707 · LLMs Know More Than They Show: On the Intrinsic Representation of LLM Hallucinations
- 作者 / 机构 / 发表处与年份：Hadas Orgad、Michael Toker、Zorik Gekhman、Roi Reichart、Yonatan Belinkov（Technion）；Idan Szpektor（Google Research）；Hadas Kotek（Apple）。**ICLR 2025 主会**。代码开源：github.com/technion-cs-nlp/LLMsKnow。
- 权威度与严谨度判断：**[顶会已发表]**。理由：4 个模型（Mistral-7B / -Instruct-v0.2、Llama-3-8B / -Instruct）× 10 个数据集，每集 1 万训练 + 1 万测试（小数据集例外），结果带 bootstrap 标准差；有对输出 logit 基线的减法校正；代码开源。弱点：正确性标签主要靠启发式字符串匹配（NQ-WC 用 Mistral-Instruct 判）；"精确答案 token"要靠外部抽取器（Mistral-7B-Instruct 少样本），抽取失败样本被剔除；无人工评估；只做检测不做干预。

## 一句话核心主张
真实性信息高度集中在"精确答案 token"（exact answer tokens · 精确答案词 · 回答里真正决定对错的那几个词）上，在那里训探针检错最强；但探针跨任务几乎不泛化（减掉 logit 基线后），说明"真实性"是多面的、按技能分的，不存在普适真实性方向；同时模型内部常常编码了正确答案却反复输出错的。

## 方法细节
- **探针**：逻辑回归（scikit-learn 默认 L2 + LBFGS），输入为某层某 token 的中间激活（他们用最后一层 MLP 的输出；预实验表明 MLP 输出 / 残差流 / 注意力头无显著差别）。层按每个 token 位置在验证集上选最优。
- **token 位置**：最后生成 token [−1]、倒数第二 [−2]、问题末 token、精确答案 token（首/末/前一个/后一个）。精确答案由启发式或 Mistral-7B-Instruct 少样本抽取（最多试 5 次，须是原答案子串）。
- **生成协议**：自由生成，贪心解码，模拟真实使用；拒答样本排除。
- **泛化实验**：每个数据集选最优 token+层，在其他数据集上训练、在本集测试；AUC 取 max(auc, 1−auc)；再减去最强 logit 基线（Logits-min-exact）看净增益。
- **错误类型**：对每题以 T=1 采 30 个答案，按"不同答案数 / 正确答案频率 / 最常见错误答案频率"分五类：A 拒答（≥半数）；B 一贯正确（B1 全对，B2 多数对）；C 一贯错误（C1 从不出现正确答案，C2 至少出现一次）；D 两个竞争答案；E 答案 >10 种（E1 无正确，E2 有正确）。覆盖 Mistral-Instruct TriviaQA 96% 的错误。
- **探针选答**：用检错探针在 30 个采样里挑"最像正确"的那个，对比贪心 / 随机 / 多数投票。

## 与 博士方案的关系
- 重叠点：
  1. "内部编码了正确答案却输出错的"正是我们 E（证据）与 C（承诺）脱节的前提证据；他们提供了量化版（C2/D/E2 类探针选答提升 30–40 点）。
  2. 他们在"问题末 token"读到强信号并解释为"编码了模型回答此题的总体能力"——这就是我们在读层训的知识探针 p(x)（P(IK) 式读数）；他们的数字（0.72–0.80）给了我们门控探针的预期上限参考。
  3. 错误类型 A（拒答）可从内部状态预测到 0.85–0.88 AUC——说明"承诺/拒答"有内部相关量，支持 C 方向存在。
- 冲突点（他们的结论会不会打我们的某条主张）：
  1. **C4 直接受威胁**：探针跨数据集几乎不泛化（减基线后），真实性编码"按技能分而非普适"。我们用 FEVER/CounterFact 真假陈述估的 E 方向要搬到 TriviaQA 类问答上，按他们的结论会掉到 logit 基线水平。必须报告"减 logit 基线后的净增益"而不是裸 AUC。
  2. **C1 受冷枝威胁**：如果真实性是多面的（多个方向），"一个 E 方向"本身就可疑；他们建议"多种不同的真之概念"。
  3. **位置问题**：真实性信号集中在精确答案 token，弱于问题末与最后 token。我们若在最后 token 估 E 或在全部位置写入，E 的估计与干预位置可能都不是信息最强处。
  4. C 类（一贯错误）与 D 类探针只有 0.59–0.68——门控的"部分已知"中间档正好对应这些类型，单探针三分档在中间档可能不可靠。
- 可借用点（方法、数据、指标、对照）：
  - 精确答案 token 定位协议（含抽取 prompt）；"减 logit-min-exact 基线"的泛化热图口径；bootstrap 标准差。
  - 30 采样错误分型法：用 B / (C2,D,E2) / (C1,E1) 三组直接作为我们"已知 / 部分已知 / 未知"三档的**行为侧真值**，比用单阈值切 p(x) 更有说服力。
  - 数据集清单与规模（10 集、1 万/1 万）、拒答排除规则、p(True) 与 logit 聚合基线实现。
- 明确差别（我们还能声称什么是新的）：
  - 他们只检测，不干预；无承诺方向、无 2×2 分离、无层选择方法、无按输入门控、无通用能力副作用评估。他们明确把"利用内部知识纠错"留作未来工作（Sec.6："not proposed here as an error mitigation strategy"）。

## 对四条主张的威胁等级
| 主张 | 威胁 | 理由 |
|---|---|---|
| C1 解耦 | 中 | 无干预实验，但"真实性多面、非单一方向"的结论让"一个 E 方向"需额外论证 |
| C2 选层 | 低 | 层按 token 在验证集选，无读写层讨论 |
| C3 门控 | 中 | 支持"内部知道外部不说"的前提，但 C/D 类（我们的中间档）可预测性弱（0.59–0.68） |
| C4 泛化 | 高 | 探针跨任务不泛化，减基线后净增益接近零 |
