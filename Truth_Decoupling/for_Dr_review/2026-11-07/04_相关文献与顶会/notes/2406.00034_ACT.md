## 一句话核心主张
在 ITI 的"注意力头上加真值方向"之上做两件事：(a) 把每道题"真答案激活均值 − 假答案激活均值"用 K-means（K 均值聚类 · 把一堆向量分成 K 堆，每堆围着一个中心）分簇，每簇单独训练探针、单独选 24 个头、各用自己探针的法向量当引导方向，推理时所有簇一起加；(b) 每个头的推动强度乘以（1 − 该簇探针给当前词的"真"概率 + β），也就是"看着越假推得越狠"。不训练底座，也不对答案做任何梯度训练。作者称在 TruthfulQA 自由生成上全面超过 ITI 等方向（数字见下表）；但自家消融显示主要增益来自"多簇方向"，自适应强度只贡献一小截，而且增益伴随有信息回答比例明显下降。

## 方法细节
- **干预位置**：和 ITI（Inference-Time Intervention · 推理时干预 · 在少数注意力头上沿真值方向平移）一样，在每层每个 attention head（注意力头 · 每层里并行的 32 个小注意力模块之一）的输出上、输出投影之前（§3.1："Our analysis and steering occur after Att and before Q"；代码 llama/modeling_llama.py 把 `self.head_out = nn.Identity()` 放在 `o_proj` 之前）。每个头 128 维，不是残差流。
- **探针**：probe（探针 · 读内部激活判断真假的小分类器），每头一个 logistic regression（逻辑回归 · 线性打分再过 sigmoid 的二分类器）。输入是"Q: 问题 A: 答案"拼接后**最后一个词元**的头激活，标签是这个答案真还是假；TruthfulQA（真实性问答基准 · 专问人类常见误解的 817 道题，38 类）重组成 5,882 个问答对（§3.1、§4.1）。
- **每题方向表示**：d = 该题所有真答案末词激活的均值 − 所有假答案末词激活的均值（§3.2；代码 generate_directions_q_wise.py L22，按"层 × 头"分别存）。
- **聚类**：论文只说"对这些表示做 K-means 得 C 簇，每簇代表一种幻觉模式"。**代码是对每个（层, 头）分别聚类**（utils.py L174–187，`KMeans(n_clusters, n_init=10, random_state=42)` 跑在该头 128 维的每题方向上）。所以"簇"在不同头之间并不对应同一批题——"不同幻觉类别各有方向"的叙事，在实现里是每个头各自分堆。
- **每簇探针与选头**：每个（层, 头, 簇）用这一簇的题训练一个探针，簇内再 8:2 切验证（验证题少于 5 道直接记 0 分）；每簇按验证准确率取前 K 个头（utils.py L195–250）。
- **写入公式**（式 2，p.4）：x_{l+1} = x_l + Σ_c Σ_h Q_l^h (a_l^h + α(1 − p_θ(a_l^h) + β) v_{c,l}^h)。默认 v = 探针参数 θ（"unless otherwise specified, the steering vector used is θ"，p.5），即 ITI 里的"探针权重方向"，**不是均值差**。代码比公式多乘一个 σ：方向取 `probe.coef_` 单位化，σ 是全部 5,882 个问答激活在该方向上投影的标准差（utils.py L253–272；σ 用了含测试折在内的全部问答，但不看标签），实际写入量 = α · σ · 单位方向 ·（1 + β − P(真)）（valid_2_fold.py L146–153）。不同簇选中同一个头时，几个向量直接相加。
- **强度怎么变**：P(真) 来自**该簇该头的探针读当前前向的最后一个位置**（valid_2_fold.py L146）；没有阈值，不做"要不要推"的硬判断。全数据设置 β = 0，只有探针给出 P(真) 接近 1 时才几乎不推。§5.4 原文："ACT introduces a logic regression on the last token of the sequence"。
- **生成时到底写了哪些位置**：评测用 Hugging Face（开源模型库）的 `model.generate`，greedy decoding（贪心解码 · 每步取概率最大的词），最多 50 个新词元，默认开 KV cache（键值缓存 · 生成时把前文算好的中间量存起来，下一步只算新词）。第一次前向是整段提示，"最后位置"= 提示末词；之后每步只输入新生成的那一个词，"最后位置"= 这个新词（transformers 4.40 的 `prepare_inputs_for_generation` 只喂还没处理过的词）。**所以"写当前最后位置"= 提示末词 + 每个生成词各写一次，写过的状态留在缓存里被后面的词看到**——和 ITI 一样每个生成位置都推，只是强度逐词、逐头、逐簇重算。
- **选择题打分时的写法**（utils.py L345–468）：把整条"提示 + 候选答案"一次前向，强度用**候选答案最后一个词**的探针读数算出，再加到全部答案词元上（valid_2_fold.py L154–155 的非 'lt' 分支）。等于让探针先看完整个候选、再决定这个候选被推多少——是"看过未来"、因候选而异的打分；ITI 原版对所有候选推得一样。
- **超参**（附录 C 表 8，p.10）：少样本 α = 15、β = 0.1、每簇 24 头、C = 2；全数据 α = 12、β = 0、24 头、C = 3（与代码默认值、README 命令一致）。少样本每簇样本太少，作者做了上采样，并改用答案末 10% 词元聚类和训练探针（脚注 3，p.6）。
- **评测口径**：TruthfulQA 自由生成报 True、Info 与主指标 True*Info（真实 × 信息 · 裁判判"真"的比例乘以判"有信息"的比例，防止全答"不知道"刷分；代码 valid_2_fold.py L188 是两折平均 Info × 两折平均 True）。裁判是 GPT-judge / GPT-info（GPT 裁判 · TruthfulQA 官方用微调过的 GPT-3 判真不真、有没有信息）的替代版：原模型退役，作者改用 OpenAI 推荐的 davinci-002（脚注 2，p.6；代码通过 OpenAI completions 接口调用使用者自己微调的裁判）。另报 BLEURT（学出来的文本相似度 · 看回答更像正确参考还是错误参考）和选择题 MC1 / MC2（选择题分 · 比较模型给各候选答案的概率）；CE / KL（cross-entropy · 交叉熵 / KL 散度 · 干预后模型在普通网页文本 OpenWebText 上偏离原模型多少）。少样本 = 5%（40 题）训练；全数据 = 2 折交叉验证。另有 NQ（Natural Questions · 谷歌真实搜索问题）与 MMLU（多学科选择题）迁移、13B–65B 规模实验（叠加 few-shot prompting · 少样本提示 · 问题前放若干示例题）、10 人人工评估、推理耗时。
- **对比方向**：CCS（Contrast-Consistent Search · 对比一致搜索 · 无监督找真假方向）、RepE（Representation Engineering · 表征工程 · 对比提示做主成分分析取方向）、Mean-Centring（均值中心化 · 目标数据激活均值减全部训练激活均值）、ITI 探针权重方向、ITI 均值差方向（mass mean shift）、随机方向；还有 IFT（instruction fine-tuning · 指令微调）模型 Alpaca、Vicuna、LLaMA-2-Chat 作为"叠加"对象。t-SNE（把高维向量压到二维看分布的可视化方法）图 3 用来说明不同类别的方向成簇。

## 与本方案（E/C 双重分离 + 等覆盖率组合）的关系
- 重叠点：
  1. ACT 是"真值 steering（引导 · 往激活里加方向让输出变）强度随当前状态变"的已发表先例。生成适配的算子 h + α·w·wᵀ(h − c) 推动量也随状态变（与投影成正比），审稿人会把两者归为同一类"状态依赖的引导"。
  2. 写入位置一样：ACT 在提示末词 + 每个生成词都写（缓存解码），生成适配也是提示末位 + 每个答案前缀位置。
  3. 都冻结底座，都不改权重。
- 冲突点：
  1. ACT 自己的数据说明"真值方向"会挪动作答 / 信息比例：主要增益组件（多簇方向）把隐含 Info 从 94% 压到 75%——这正是我们说的 E 与 C 混在一个方向里。若生成适配或 E 臂拿 TruthfulQA 的 True / True*Info 和 ACT 比，必须同时报"空答 / 不答"比例或在同作答率下比，否则对方数字里有一部分是"少答"换来的。
  2. 公开数字不可比：替代裁判、LLaMA-1/2 代模型、单次运行；不能当"我们比 ACT 好 / 差"的依据，真要比只能同环境重跑。
- 可借用点：
  1. **零梯度对照**：ACT 式"探针读当前词 → 强度乘（1 − P(真)）"可以直接套在我们的 DAS（Distributed Alignment Search · 分布式对齐搜索 · 学出能换掉高层变量的那个子空间）或均值差方向上，当作生成适配的"不训练、只按状态调强度"对照，回答"收益来自 CE 内容训练，还是只来自状态依赖强度"。
  2. "隐含 Info = True*Info ÷ True"这个拆法，可以用来拆任何只报 True / True*Info 的论文。
  3. 表 1 那种"多种方向同一裁判比较"的格式（随机、CCS、RepE、均值差、探针）可以沿用，但要加误差条和独立调参集。
- 与生成适配、回退候选逐项对照：

| 维度 | ACT（论文 + 代码） | 生成适配（GPT 实现） | 回退候选（GPT §3） |
|---|---|---|---|
| 底座 | 冻结 | 冻结 | 冻结 |
| 训练什么 | 每（层, 头, 簇）一个逻辑回归探针 + K-means；**对答案内容零梯度** | 单位向量 w（d 个参数），正确答案逐词 CE、按长度平均 | 不训练（用现成方向 + 检测分数） |
| 写在哪 | 若干注意力头（每簇 24 个，最多 3 簇） | 单层残差流（Qwen3-8B 第 34 层） | 待定（拟用 DAS 方向） |
| 方向 | 各簇探针法向量，多方向相加 | 一个方向，DAS / 均值差 / 随机初始化后训练 | 一个已验证方向 |
| 强度 | α·σ·（1 + β − P(真)），逐词逐头逐簇重算，**永远朝 +真 方向推** | α·wᵀ(h − c)：沿 w 把偏离中心 c 的量放大（1+α）倍，**状态在哪一侧就往哪一侧放大** | 固定强度 |
| 写入时机 | 提示末词 + 每个生成词（缓存） | 提示末位 + 每个答案前缀位置（训练与缓存解码一致） | 先不推，检测到再回退重生成 |
| 阈值 / 回退 | 都没有 | 都没有 | 有（一次） |

- 明确差别（我们还能声称什么是新的）：
  1. ACT 没有任何对答案内容的梯度训练，只有探针（用参考答案的真 / 假标签）和 K-means；"用正确答案逐词 CE 直接训练方向"不在 ACT 里。
  2. 推动的符号逻辑相反：ACT 永远往"真"那边加、越像假加得越多；生成适配是围绕中心 c 的放大，本身不带"朝真推"的符号。写作时要讲清，也要实测"原本落在假一侧的状态"会不会被推得更假。
  3. ACT 是注意力头级、多方向；我们是单层残差流单方向。
  4. ACT 没有作答 / 弃答方向、没有判别力指标、没有等覆盖率比较、没有 DAS——N1、N2、N3 都是空位。
  5. 回退候选在 ACT 里找不到依据：ACT 不回退、不做"要不要推"的硬判断，只逐词连续调强度；回退的文献依据只能引 FASB。

## 对三条主张的威胁等级
| 主张 | 威胁 | 理由 |
|---|---|---|
| N1 双重分离 | 低 | 只有一个"真值"目标，没有作答方向，也不测判别力；它的数据（多簇方向让隐含 Info 从 94% 掉到 75%）反而支持"真值方向混着作答成分"，是我们的论据。 |
| N2 等覆盖率组合 | 低 | 没有选择性作答、弃答或覆盖率；"自适应强度"是连续调推力，不是答 / 不答；True*Info 不是同作答率准确率。 |
| N3 DAS 胜均值差 | 低 | 不含 DAS；虽在同一裁判下比较了均值差类方向与探针权重方向，但单次运行、Mean-Centring 那格自相矛盾，不构成对 N3 的证据。 |
