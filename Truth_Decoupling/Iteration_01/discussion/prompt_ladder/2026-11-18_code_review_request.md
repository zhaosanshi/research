## 4. 做法

- **只换系统提示**。同一个方向文件、同一层、写入量为力度 2 乘以该运行的 gap、写入位置相同（从用户问题起到末尾，包括每个生成步）、对话模板、贪心生成、最多 48 个新词元、每批 8 题，都与现有条件"必须作答问法 + E 力度 2"相同。
- **为什么不能只改配置**。`e44_eval_extra.py` 只能把新提示拼成"三种基础提示之一 + 运行提示文件里的句子"，而运行提示文件属于运行身份的一部分，加句子会使身份校验失败；P1 至 P3 也拼不出来。它还只写入运行目录下的 `eval_extra/`，那里已有同名而来源不同的文件。
- **内存中的三处改动**：
  1. `extra_systems` 换成从提示文件逐字读取新提示，保留原有的检查（名字格式、不与运行已有的提示重名、不出现重复文本）；
  2. `Context` 的输出目录改为单独的目录；
  3. `run_export` 的输出目录改为同一目录：对源码中的一行做精确替换，必须恰好匹配一次，否则不运行。
- **对照**：每个数据集在跑 P1 至 P3 之前，先用同一条路径重新生成"必须作答问法 + E 力度 2"，必须与原有文件逐词元相同，才继续。
- 输出放在 `promptladder/runs/<运行目录名>/`（服务器），不写入运行目录、代码副本或 `diag/`。

## 6. 请重点审的地方

1. 第 4 节的三处改动，是否可能改变写入、被写入那一段的渲染，或生成本身。对照一步是否足以发现这类问题。
2. P1 至 P3 的措辞：由谨慎到坚决的这一档序对提示词一方是否公平，有没有使它吃亏的写法。
3. 候选题：普通问法下推 E（力度 2）后按规则判为留空的题，与 C 分档一方相同。题数：调参集 Llama-3.1-8B 77、Qwen3.5-9B 50、Qwen3.8-27B 63、Gemma-3-12B 76、Gemma-3-27B 31；测试集 523 题中依次为 211、114、157、176、90。
4. **判分的范围**。导出的回答中，除了三种新提示下带 E 的回答和对照之外，还有每种新提示不写入时的回答。比较只需要前者。现有的判分程序只能限定题目、不能限定条件。只判前者约 1.5 元，连同不写入的回答一起判约 3 元。建议一起判，省去为此新写程序；不写入的回答也可以作为"只换问法"的参照。是否同意？
5. Qwen3.8-27B 原来用两张卡自动分配运行，单卡运行是否逐词元相同没有证据。由对照一步判定；不一致就照原样用两张卡。
6. 计算两方得分与相同预算比较的分析程序尚未写，将在生成完成后离线编写，不占 GPU。
