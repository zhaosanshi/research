## 3. 请重点看的地方

0. **`main_table_layers.py` 与 `alt_layer.py`：换层有没有偷看测试集**。事实经过要先交代：想到去看 Llama 的第 16 层，是因为 MMLU 的分层图（1,000 道诊断题）显示这一层不掉分；随后做过一次只推 E 的探查，那次判的是 TruthfulQA 的**测试集**（`launchers/explore_20261120/layer_probe.sh`）。所以"去试第 16 层"这个念头用过测试集的数字。现在主表的规则只用调参集与 MMLU"选力度"的一半：每层先取预算内最大力度，再比两层在该力度下 N1 的调参集净分（Llama：第 11 层 0.75 为 +6，第 16 层 3.5 为 +26）。请判断这样交代是否足够，或者需要在别的题上再确认一次。两个 Gemma-3 的候选层（第 28、24 层）只看过 MMLU 分层图和早先的调参集判分，没有碰过测试集。
1. **`per_model_table.py` 的选力度规则有没有偷看**。力度只由 MMLU 的“选力度”那一半决定；N1 的两个上限在该力度的 TruthfulQA 调参集上选；TruthfulQA 测试集与 MMLU 的另一半只用来读数。请核对半分用的种子与 1,000 道诊断题的归属（全部在“选力度”的一半里）。
2. **`ns_stable_table.py` 与 `ns_probe_table.py` 的保留规则**。两者都只会给出模型不写入时的回答或者留空；“回答相同”用的是 N1 规则里现成的比较函数（`release_origin.norm`）。请核：留空的回答会不会被记成对或错；各遍回答之间题目顺序是否对齐；第二批测试题用的是另一个题库文件（`*_bank_test2_20261120.jsonl`）；族内成员在调参集上选、并列取靠前（较弱）的一个。
3. **`ns_probe_table.py` 里两处对照的口径**。“换问法”对照用的是必须作答问法那一遍回答与不写入回答是否相同；“按把握挑题”对照用必须作答那一遍、按回答词元的平均对数概率保留同样多的题。两者与“用 E 复核”比的是同一批题、同样的记分。
4. **`ns_caut_confirm.py` 的选择集**。它把调参集与第一批测试题合在一起选设置，这是有意的：第一批测试题在探索各种变体时已经看过，结论只读第二批。请核它有没有任何地方用到第二批题的数字来选。
5. **别名匹配的已知偏差**。否定句里出现标准答案字样也会被判对（例如“某某并没有写这部剧本”）。这会抬高“只推 E 直接作答”的分数。本批所有新题集数字都是别名匹配判的，没有新的 Pro 判分。

## 4. 已做的自查

- 另起一个子代理（Opus 5.5）只读代码、专挑错：`ns_stable_table.py` 的保留规则用六道假题走真实的记录函数测过，各上限下结果都符合定义；双写入的臂名、并列时的取舍、选设置只用调参集、各遍回答的题目对齐，读代码未见问题。它指出四处，核对属实并已修：`ns_probe_table.py` 在第二批题上建不出“按把握挑题”对照时不说明原因（现在会打印原因）；`ns_stable_table.py` 只要有一个模型缺一项比较，五个模型的合计就整段不打印（改为逐项判断）；`ns_caut_confirm.py` 缺不写入那一遍回答时直接报错退出（改为按模型提示）；读回答文件时没有核对文件里记的臂名与生成器版本（已加）。修改前后在同一批数据上的输出，除去两次运行之间新生成的回答带来的行以外，逐行相同。

- 主表程序（`main_table_layers.py`、`alt_layer.py`）也另请子代理只读审过一遍：未发现会让数字出错的地方；按它的提醒加了三处防护（一个模型的两层必须是同一份题目清单，否则报错；另一层的判分目录里重判的不写入回答必须与原表一致，否则报错；五个模型的合计只在五个模型都有判决的题上算，并打印题数）。`per_model_table.py` 的合计也改成了同样的口径，分模型的各行不变。
