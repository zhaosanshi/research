# 目录规则

撰写：赵磊（Opus 5.5 代笔）。起始日期：2026-11-16（北京时间）。

Iteration_01 是 Fable/Opus 与 GPT 共同讨论、形成概念的地方。

## 1. 目录

```text
Iteration_01/
├── charter/                  统一要求
├── doctor/                   与博士的往来
├── discussion/               共同讨论
│   └── questions_to_confirm.md
├── literature/               文献
│   ├── references.md
│   └── novelty_analysis/
├── draft/                    论文草稿
├── code/                     程序
└── results/                  结果汇总
```

## 2. 各目录的内容

1. `charter/`：统一要求，全体参与者均须遵守。文件名为"类别号_序号_名字"，类别号越小，效力越高：00 为整体文档的规则，10 为论文的规则。
2. `doctor/`：与博士的往来，包括博士的建议与赵磊的回复。不按日期另建文件夹；文件名以日期开头，并写明是建议还是回复。博士的建议照录原话，文中只称"博士"；含姓名的原件只存本地。
3. `discussion/`：共同讨论。一个议题一个文件夹，参与各方均可在其中新建、修改文件，修改记入该文件的变更记录（见 00_01）。待确认的问题汇总于 `questions_to_confirm.md`。
4. `literature/`：文献。
   - `references.md`：参考文献清单，每篇写明等级标签（见 10_02）、会议、编号与链接。论文 PDF 只存本地。
   - `novelty_analysis/`：论文创新点分析。每次检索一个文件，先写冲突，即他人做了什么、与本研究有何差别；再写缝隙，即按该次检索，尚无论文同时做到的内容。
5. `draft/`：论文草稿。正文按章节分文件，图与引用文件（.bib）一并存放。
6. `code/`：程序，从服务器按需迁入，供审核与讨论；规则见 10_04。
7. `results/`：供讨论使用的结果汇总，分层方式见 10_04 第 6 条；模型原始输出与逐题判决保存在服务器。

## 3. 博士必读的内容

以下三处为博士必读，其余目录为讨论过程：
- `draft/` 中的论文草稿；
- `doctor/` 中给博士的回复；
- `literature/novelty_analysis/` 中的论文创新点分析。

## 4. 文件命名

1. 目录名与文件名用英文。
2. 持续更新的文件用固定名字，例如 `questions_to_confirm.md`、`references.md`。
3. 记录某一时点的文件，文件名以日期开头，格式为 YYYY-MM-DD，例如 `2026-11-16_ec_separation_prior_work.md`。
