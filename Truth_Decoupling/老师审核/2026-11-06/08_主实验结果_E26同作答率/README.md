## 实验怎么做的

- 固定题集上，每种方法先生成候选答案，再按分数只交付 25% / 50% / 75% 的实质回答，其余一律交付"I don't know."；模型自己的拒答不能填额，回答不够就标"不可行"。比较的是交付集里答对多少。
- **离线评测边界**：排序分不看金标，但问答候选是否属于“实质回答”，由收到参考答案的外部语义裁判标注。A/B 对错一律可选，只排除未尝试 C；不据此宣称线上无需判分即可精确填 K。原生 Yes/No 门控可以在线发候选，实际实质作答率仍须离线标注后统计。
- 方法：不加干预的原模型（按承诺分、简单置信、随机三种挑题方式）；只推 E、只推 C、E+C（DAS 与均值差两种方向）；以及 E、C 配简单置信挑题。"承诺分"是模型对"你知道 / 能答这题吗"首词 Yes 减 No 的分数（即老师建议的 C 定义）；"简单置信"是真假判断里真假对数概率差的绝对值、问答里答案的平均对数概率。
- 每档作答率下的配置在 192 道调参题上独立选，529 道测试题上报告。完整分析计划（主对比 = DAS 的 E+C 对 E，12 格 Holm 校正）已在测试前提交；不能称为“任何结果出来前”：正文 18:30 与 Git 提交 18:27:09 不一致，且提交与真假调参落盘仅差秒级。分析脚本 19:17 提交时真假测试已生成，仅问答判分尚未完成。没有证据据此推定看过结果后改方案，具体见 [`06` 时间线核对](../06_审核记录/README.md)。
- 限制：TruthfulQA 共 817 题已全部用过，测试集在前几轮看过，这是"已看过的测试集上的比较"，确认需要第二个数据集。

## 结果

| 问题 | 结果 | 对论文 |
|---|---|---|
| 相同作答率下，E+C 是否胜过只推 E（主对比） | **本次未证实。** 12 格差值 −3 到 +9 题，Holm 校正后 0 格显著 | 对本次实现：消极 |
| 只推 C 是否有用 | **本次固定配额表未显示稳定收益。** C 明显移动承诺分，题目排序变化较小（秩相关 0.96–0.998），但不是严格纯平移；需用原生交付和固定 E 消融检验作用 | 支持门槛解释，但未证明 C 只有这一作用 |
| 推 E 是否有用 | **真假判断上有用**：推 E 对原模型（都按承诺分挑题）50% / 75% 两模型都显著（+26 到 +40 题）；推 E + 简单置信对原模型 + 简单置信，Llama 显著（+40 / +44），Qwen 未过校正。**这套自由问答实现未显示稳定收益** | 真假判断：积极；问答：消极 |
| 承诺分适不适合挑题 | **很差。** E+C 在真假判断 5 个格子里显著输给简单置信挑题；原模型按承诺分挑题，75% 档比随机还差（Qwen −49，校正后显著） | 新发现 |
| C 能否调动实际作答 | 同一 C 把“能答”的自报比例从 0.33 推到 0.73；把它迁移进另一套答案提示后，实质回答只变几个百分点。**尚未由该结果测出原生 Yes/No 门控的实际交付范围** | 提示迁移与交付连接须分别检查 |
| GPT 第 18 轮的生成适配（E27）正结果 | 发布版代码复现数字；质量口径下收益脆弱，尚未证明 DAS 初始化的独立优势；Llama 没有稳定收益。算子属于已发表 LoReFT 的秩 1 绑参特例，位置策略不同 | 不能充作纯 DAS 的自由生成突破 |

## 对下一步的含义（请老师判断）

1. 本次实现尚未支持老师的主句。数据支持较窄的说法：**当前 E 在真假判断上保留提升，当前问题级自报承诺分是较差的筛题信号，简单置信是必须保留的强对照。** 不能据此宣布所有承诺方向无效或所有 E+C 方案不成立。
2. 改写主张中"现有真实性 steering（ITI、CAA、TruthX）的提升多来自多拒答"那一半还没测——这需要在 TruthfulQA 自由生成上做同作答率重评。
3. 当前自由问答配置未显示稳定收益。第 20 轮先检查承诺门控的实际连接与真实源交换；是否有效必须由新运行给出，不能预设正结果。
4. 需要第二个数据集（建议 BBQ）做确认。

**补充（探索性）：Qwen 带生成适配器的同作答率版本也已跑完**（报告 `14` 第 5 节）。自然作答率下多答对的收益，在相同交付份额下没有显示稳健优势；DAS 起步原判 +13 的格子也依赖输出质量口径。在适配器上叠加当前 C 同样未见稳定收益。结果说明必须区分“答得更多”和“同样多回答里答得更准”，但尚不足以把所有生成变化都归因于作答率，更不能外推到未复现的其他真实性方法。

GPT 第 19 轮（`edcd02a`，11-06 深夜）对 E27 做了自查，有三点发现。第一，"随机起步"的收益来自随机起步之后追加的正确答案训练；真正不训练的随机方向，在 192 道调参题上只有 ±1 题。第二，乱码来自个别生成步骤写入过量。第三，把部署力度降下来，乱码消失，但收益也没保住。GPT 主张停止扩展 E27。Claude 后来已在提交 `1ffaedf` 的第 15 份报告中复核，复现主体结果，同时提出三个仍须落实的要求：同实际作答率、实际写入尺度匹配的随机控制、重新训练的无额外题目内容来源控制。本轮逐项补充，详见 `06` 第 1 节。

## 结果核查：逐题复算一致，设计与实现仍须分别审核

**审核状况**：E26 的实验代码由 GPT 编写，GPT 自己做过方法红队；Claude 开跑前也独立审过，包括服务器上 193 / 193 项测试、三条真实模型三题试点、逐行代码红队和 C 剂量探测。

开跑后，Claude 又写了独立脚本 [`review_checks/e26_independent_recount.py`](../../../claude_gpt_review/from_claude/code/scripts/review_checks/e26_independent_recount.py)。它不导入 E26 代码，按同一配额规则从逐题原始记录重算：

| 核查 | 结果 |
|---|---|
| 测试集主表：每个方法、每档作答率的交付答对数 | 244 个格子与 `report.json` 零差异 |
| 调参集上的冻结选择（答对最多，并列取更小干预） | 225 个与 `selection.json` 零差异 |
| C 是否真的写进模型 | 承诺分平均平移 Llama +2.68、Qwen −11.78，与开跑前剂量探测（+2.57、−11.91）一致 |
| E 是否真的写进模型 | 真假判断翻转 Llama 74、Qwen 83 题；问答里 E 每个生成词元写一次，C 在提示末位写一次，回答原文改变 56–114 题 |

**第 20 轮收窄后的结论**：上述复算没有发现主表计数或冻结选项不一致。固定配额对严格单调的分数变换不敏感，但当前 C 并非已证明的严格平移；“变化主要在门槛”只是解释。还须检查 C 的提示迁移、原生交付连接、固定 E 对照，以及统计和来源校验，不能把独立重算当成所有错误都被排除。

补充诊断按强度扫 C，用首词 Yes/No 的决定实际控制交付，再与“不动模型/固定 E + 门槛”比较。它补足门控机制检查，**不替换原固定配额主表**。原先“实际作答只变几个点”来自把 C 写到答案提示后的生成变化，不能预先断定原生门控曲线也只能很短。

**第 20 轮已审核**：Claude 的启动和分析脚本、原主运行/适配器的冻结选择与统计、相关真实产物均已完成对应范围的独立核查；244 格和 225 个选择一致，1848 个精确检验及旧自举区间也一致。审查范围、原件与未推广的边界见 [E26 复审](../../../claude_gpt_review/from_gpt/audit_20261107_round20/e26/review.md)，不再沿用旧稿“尚未经 GPT 审”的状态。

## 第 20 轮：修了什么，跑出来怎样

1. **补齐公平对照。** 旧表缺少组合也按简单置信筛题的一臂。本轮按原调参规则补齐所需测试候选，原主表不覆盖。统一简单筛题后仍没有组合稳定胜过 E 的证据。[补齐表](../../../claude_gpt_review/from_gpt/audit_20261107_round20/e26/joint_simple_extension_report.md)
2. **C 确实能改变交付多少，但没有因此挑得更准。** 原生门控与预设四层都已实际运行。只写门控时，问答交付范围远不止几个百分点；同数量与简单筛题比较仍弱。不能把 C 说成没接进模型，也不能把多交付带来的多答对当同率收益。[原生诊断与修正口径图](../../../claude_gpt_review/from_gpt/audit_20261107_round20/native/review.md)
3. **门控混淆了“答案是真/Yes”和“我能确定答案”。** 真假判断明确改成：能确定真或假都应 Yes，并重新估 C、重新完整跑主表。50% 简单筛题下，原模型/E/C/E+C 为 Llama **417/457/425/453**，Qwen **453/470/449/472**；每组实际交付 529 条。组合对 E 六格校正后均不显著，不把 Qwen +2 单格当成功。[新真假表](../../../claude_gpt_review/from_gpt/audit_20261107_round20/tf_ability/summary.md)
4. **纯个人不知道不能算正确回答。** Qwen 同一题“I don't know.”在多方法被误判 A，现用不看参考的完整句守卫修复未来判分，旧原件留存并统一派生侧表。三套旧 QA 调参选择全部不变，旧测试标签零变更，旧主表不因它翻盘。[守卫与影响范围](../../../claude_gpt_review/from_gpt/audit_20261107_round20/refusal_guard/README.md)
