## 2. 排序指标的条件缺口：allclose不保排序

代码位置：新 `e23_merge.py` 加载段，`np.allclose(bP0,bP_,rtol=0,atol=1e-6)` 与0.5阈值预测相同比较。聚合基线只比较 `ans/J/B`，没有比较AUROC；随后所有条件共用首块的逐题基线。

构造4道题，每道一真一假，前2道调参、后2道测试。两块基线分别为：

```text
第一块：真句0.6000001，假句0.6000002
第二块：真句0.6000002，假句0.6000001
```

所有概率都超过0.5，因此真假预测逐项相同；自报也逐项相同；每个概率只差 `9.9999999947e-8`，小于允许误差。两块J、偏置、自报聚合值全部相同。但第一块AUROC为0，第二块为1。

第二块某个候选在调参上表现更好，因而按原规则被选中；它在测试上**逐句等于自己的基线**，真实的测试效果严格为0。新代码仍接受两块并共用首块基线，得到：

| 测试指标 | 正确结果 | 新代码报告 |
|---|---:|---:|
| ΔJ | 0 | 0 |
| Δ自报 | 0 | 0 |
| Δ偏置 | 0 | 0 |
| ΔAUROC | **0** | **+1** |
| ΔAUROC的95%区间 | **[0,0]** | **[1,1]** |

这说明概率数值很接近，并不限制排序统计的差异。只要正负分数间隔足够小，允许误差可以任意缩小，AUROC差仍可达到1。因而不能靠把容差从 `1e-6` 改到另一个小数，就获得一般正确性保证。

### 最低修法

最简单可靠的是：**要让所有条件共用同一逐题基线，就要求基线概率数组逐项完全相同**，并保留现有答案／预测一致检查。已核的两模型合法分块满足这个条件。

如果确需允许不同概率，则至少要保证被报告的每种统计在任何题重采样下等价。对AUROC，一项充分条件是所有对齐的正负样本两两大小关系及同分关系相同；仅检验全局AUROC相等仍不够保证配对重采样区间相同。这条实现更复杂，当前没有必要优先采用。

另一种办法是每个条件保留它所属运行自己的基线；但那改变了“同一扫描分块”的统计接口，不能默默混入当前合并逻辑。

## 3. 身份字段守卫的边界

`run_identity()` 对每个字段调用 `j.get(k)`，然后比较块之间的结果。它能拒绝**已记录且不同**的值，但“缺失”会变成None。

独立测试：

- 仅一块缺 `e_estimator`、另一块写 `meandiff`：正确拒绝。
- 两块同时缺 `model/e_estimator/wording`：仍接受，原因是None等于None。
- 两块都写 `model="OTHER_MODEL"`，存放在被调用的fixture目录，以 `--model fixture`运行：仍接受，最终报告模型名为fixture。

这些输入不代表现有真实两模型有问题；它们说明守卫还不能确认不完整材料的来源，也不能保证输出模型标题与输入一致。

最低处理：至少要求模型等核心身份字段存在，并验证模型名等于命令行要求；对必须识别的估计器／提示协议，缺失时应显式拒绝，或进入清楚标明的旧材料兼容路径并补齐来源。诸如历史文件没有 `est_extra_pairs` 之类可明确解释的可选字段，与缺少模型身份不能一概当成None相等。

## 4. chk_merge_guard 本身覆盖到了什么

其正常路径从真实单个扫描拆块、反序合并；参考选择使用新整数规则，避免把原始JSON中旧浮点误选当正确答案。这一点正确。

四类冲突测试分别覆盖较大的逐题基线改变、标签、模型、估计器，均有效；但没有覆盖“阈值预测相同、微小概率差导致排序／同分关系变化”，因此全部通过不代表排序边界已关闭。本轮的新增独立反例补的是这条边界，不否定已通过的检查。
