# 自由问答代码复审：确认的问题、评分修复及 E25 必须先改的设计

审阅 GitHub 提交 `e438514e7b17672eef8b9d38d0bda883af92b3c5`，包括 `03_请审_真实问答验证代码与方向上下文.md`、E24生成/干预/判分链及旧E4/E4b代码；另从Pro5000核对了实际96题估计数据。未重新生成模型答案。

**结论：有确定的评分错误和证据对比数据污染，拟议E25还存在会漏掉首词的预测位置错误。但没有发现E24因钩子漏执行、跨批次计数耗尽或缓存不传播而静默失效。**

## 1. 方向来源与任务确实不一致；只换中点不等于换方向

`e24_real_qa.build_directions` 实际使用：

| 方向 | 估计时的任务 | E24使用时的任务 |
|---|---|---|
| E | 对给定陈述判断True/False；载入该任务下训练的DAS方向 | 只给问题，让模型生成答案 |
| C | 对原问题自报“知道吗”，回答Yes/No；按提示差或自评分组估计 | 只给问题，让模型生成答案 |

因此，03文档把C也写成“在真假句提示上估”，不准确。C的真实迁移是“自报是否知道→实际作答”。

E24重新计算了问答提示下的中点`cQ`，但`wE`仍是原来的方向；中点修正只能去掉一部分整体偏移，不能证明该方向已经表示自由回答中的真假证据。

**这一步是此前双方约定的固定旧配置迁移验证，不是Claude漏跑了一个已约定的QA重训步骤。**其负结果应表述为“当前旧配置没有直接迁移出可靠问答收益”，不能扩成“在QA上下文重新估计的方向也无效”。下一步在QA上下文重估是合理的待验证方案，但不能把尚未验证的迁移当成已对齐任务。

## 2. 实际96题中有7个E正例是个人弃答

已直接核对Pro5000的 `truthfulqa_tf/calib.jsonl`、`dev.jsonl` 和 `truthfulqa/all.jsonl`。96道估计题中，7题第一条正确答案为 **I have no comment**，且旧真假转换确实把它拼成：

```text
The answer to the question "..." is: I have no comment.
label = true
```

题号：624、583、70、379、592、625、83。完整原文见 [估计集核验](./estimation_answer_audit_20261102.json)。其中3题还有其他非纯拒答参考，4题没有。

**问题不是TruthfulQA允许拒答的标注本身错误，而是这些样本不适合直接充当“纯证据”对比。**它们把“事实正确”和“不表态”混入同一正类，恰好与要分开证据和承诺的目标冲突。7/96不能证明所有失败都由此造成，但03拟议再次直接取`gold[0]`，会把这个问题复制到E25。

最低修法：E的数据构造时，先识别个人拒答型参考；有实质正确参考的按预定规则替换，没有的从E对比中单列排除并报告数量。不能偷偷从调参或测试集补题，也不能用包含`unknown`的宽泛匹配把客观未知的事实一起删掉。

## 3. 两处确定的评分错误，已改代码并重算

### 3.1 关键词不能推翻语义裁判

旧逻辑是“规则命中或裁判判弃答，最终一律弃答”。它会把 `Unknown Cape Cod.`、`Unknown Plato.`、`Unknown, but likely cryogenically frozen.` 这种给出了具体答案的输出强制记成未作答。

已新增 `core/qa_scoring.py`，E24改用裁判标签，规则只记录分歧供复核；未判定仍保留未判定，不借关键词补成弃答。新增 `--phase rescore`，可以完全复用旧裁判结果，零API调用、零模型生成，旧输入与旧报告不覆盖。

只修标签合并、保持旧521题分区时，Llama C：

| 指标 | 旧规则 | 取消关键词覆盖 |
|---|---:|---:|
| 答对 / 答错 / 弃答 | 116 / 198 / 207 | **127 / 222 / 172** |
| 相对原样的弃答增幅 | +24.95个百分点 | **+18.23个百分点** |
| 相对原样的答错变化 | −19.96个百分点 | **−15.36个百分点** |
| 相对原样的答对变化 | −4.99个百分点 | **−2.88个百分点，区间[−5.76,0]** |

所以效果幅度被夸大，旧的“答对显著下降”也需撤回；但“更多弃答”的总体方向没有反转。Qwen的反向行为仍在，两模型E仍无可靠问答增益。

### 3.2 同一个宽泛规则还删掉了正确参考答案

旧代码用 `rule_abstains(gold)` 过滤参考答案，会把 **The origin of the phrase is unknown** 这类客观事实也当成个人拒答。题399、407因此被错误地排除在主表之外。

已改为精确匹配完整的个人拒答模板，保留“客观未知”的参考；记录实际送给裁判的参考列表。列表变化时强制重新判定相应题，避免沿用旧标签。旧分区的缓存重算仍独立保留，便于隔离两项修复的影响。

已经在Pro5000的隔离目录执行修正后的判分：14道题的裁判参考列表发生变化，所有条件均重新核判相关项；模型答案逐字未变，未重新生成。仅个人拒答型金标题为6道，修正后的主表为523道，未判定为0：

| 模型／条件 | 答对 | 答错 | 弃答 |
|---|---:|---:|---:|
| Llama 原样 | 143 | 303 | 77 |
| Llama E | 145 | 304 | 74 |
| Llama C向弃答 | 129 | 222 | 172 |
| Qwen 原样 | 137 | 195 | 191 |
| Qwen E | 136 | 196 | 191 |
| Qwen C向弃答 | 157 | 199 | 167 |

主要判断不变：E没有测到可靠提升；Llama C增加弃答；Qwen C的弃答反而减少。Llama C答对率下降、Qwen C答对率上升的区间现在都包含或碰到零，不能把它们写成稳健的正确率改善/损失。

**修复的边界：**取消关键词覆盖不等于裁判全对。已有裁判仍把“Unknown，Japan是强候选”“Unknown，随后列举具体法律情形”判成弃答。已对166条非简单模板的规则命中回答做条件盲化的AI复核，得到53条实质答复、100条纯弃答、13条类型歧义；正确性另有29条未解决。它们已列为审查材料，没有自动覆盖成一份伪装成人工金标的新结果。因此当前仍是单裁判重算，不是完成了双模型族与人工仲裁的最终评测。

## 4. E25计划有一个会让首词完全不受干预的硬伤

03§4第3步说“只对答案各位置写，对提示不写”。设提示长度为P：

```text
位置 P−1：最后一个提示词 → 预测第一个答案词
位置 P  ：第一个答案词   → 预测第二个答案词
```

若从P才开始写入，第一词的预测就被漏掉。单词答案且不计结束符时，整条候选答案得分都可能不变。

最低修法：目标答案位置 `[P,…,P+M−1]` 对齐预测位置 `[P−1,…,P+M−2]`。要控制全部答案词，就必须包含最后一个提示位置；左填充时按每行实际边界计算，不能硬编码偏移。答案末位置的表示也不能与“生成这个答案词之前”的状态混为一谈。

已用真实Hugging Face小型Llama在CPU验证：只改答案所在位置，首词预测变化为 **0**，它后面的预测却变化约 **0.494**。**这是E25待实现方案的错误，不是已经导致E24零收益的错误。**

## 5. E25还有两处需要在实现前改清楚

- 一真一假两条答案的概率比较，应叫“配对答案选择准确率”。官方MC1要比较指定最佳正确答案与全部错误答案中的最高分，不能只取`incorrect[0]`就沿用官方指标名。
- 现有三条谨慎提示全部指定`Unknown`，平均三种措辞并未从设计上去掉这个固定词的混淆，不能视为已经消除词汇绑定；再用规则命中率选C，会继续奖励“在答案前加Unknown”。QA对比提示应不指定固定弃答词，选C要按是否实际提供答案判断。

此外，E25从旧DAS换到QA均值差，同时改上下文和写入模式，不能把任何收益全归于上下文。若要验证上下文原因，至少留一个同估计器、同写法的对照；若只是探索新方法，也应如实写出这些同时变化。

## 6. 已排除的实现猜测，以及旧对照不能排除的事

我亲自重跑了 `verify_real_qa_path_20261102.py`，调用当前生产干预钩子、CPU随机初始化小Llama：

- 同一批只写一次后，后续层的缓存发生变化；给两边完全相同的下一词，输出仍有差异，说明改动会传播。
- 缓存生成与固定原提示位置的完整重算最大误差约 **6.71×10⁻⁸**。
- 连续两个批次都实际写入一次，`max_calls`没有跨批次耗尽。
- 真正的E24输出中，Llama E有83/529条文本改变，Qwen有36/529条，不能说整条干预链没执行。

C的正负号也没有发现算反：自信−谨慎、Yes−No，负强度朝原估计任务的谨慎/No组推；它在自由问答中的行为反向，不等于数学符号写反。

旧E4b则直接将真假提示的中点用于QA，E24已经重算QA中点；旧对照还改变了估计器、层、强度和题集。因此“旧连续模式也失败，所以已排除写入频次、唯一原因就是方向来源”不能成立。旧结果可作失败记录，不能作单变量排因。

## 7. 给Claude的执行结论

**E24评分修复已实现并验证；E25原方案不能原样开跑。**先修正E正样本构造、首词预测位置与C的选择口径。实现后先用1–3道题核对真实输入、目标答案位置和预测位置，确认单词答案的首词分数确实能受干预，再扩大运行。

本轮没有重训QA方向，没有宣称已经找到提高自由回答正确率的方法。代码与数据修好之后，才有资格用新实验判断这件事。
