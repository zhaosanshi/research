# 第22轮：自由回答判分与候选选择的代码审核

最初锁定 Git `cf8f752245e0265b20fdab65b2d24de0339e0383`，随后合入 `5563bd8` 对报告时间锚点的更正；后一个提交没有修改所审代码。本轮重点审自由回答原文→裁判→合票→人工→统计，以及E42怎样从候选里选答案。原始回答、旧v5票和既有结果均未覆盖。

**确实有会改变结果的实现错误，也有不能靠改程序就宣布解决的判定标准问题。** 旧105项自检和27项人工流程检查原本都能通过，但没有覆盖下面几条实质路径。本轮用故障样例、两批完整原件和真实分词器/GPU检查复现后修复，包含我以前写的缓存与参考校验中的遗漏。

## 1. 最重要的实际错误：候选选择把问答方向读反了

E42只给真假训练方向定了正负，却把问答方向的原始符号直接用于“分数越高越真”。实际使用的问答方向在第28/29/30层，与对应真假**方向估计样本**的真减假均值方向点积都为负，约−0.0561/−0.0472/−0.0511。银行指纹、方向字节、估计样本和提示词来源均独立核对一致；这些样本与本次192题不重叠。

同一条轴的正反号在投影写入时可以抵消；拿它的有符号坐标挑最高答案时，正反号却会把选择颠倒。这处错误在**读出选答案**，不能拿来解释此前所有生成失败、乱码或E+C结果。

不重新生成、不重判，只用同一批保存的候选和旧v5标签回放：

| 选择规则 | 改变的答案文本/192 | 旧评分中的A数 |
|---|---:|---:|
| 原问答方向跨层均值 | 0 | 67 |
| 只修符号 | 156 | 83 |
| 只修代码声称做过、实际没做的逐层标准化 | 1 | 67 |
| 两项同时修 | 156 | 82 |

简单的真假判词对照原来已有84，仍高于82。**这些数字证明程序错误有实际影响，不证明新方法胜出，更不是新的真值或未见题确认。** 完整逐题变化、未决上下界和训练来源见[选择修复回放](audit_20261108_round22/metrics/readout_replay.json)。

另外，部署用的select分支原来还读取gold并构造一个不用的参考答案提示；没有gold就会崩溃。已移除这个依赖。192个真实问题去掉gold后，模型实际用到的两套提示词元与旧原件完全一致。这是接口错误，**没有证据表明旧select把gold提示实际喂了模型**。

## 2. 真实触发的判分统计错误：B不一定表示有信息

B的定义是“含假信息”，它可能同时没有回答到点。旧代码却把A+B一律算作实质作答，导致同样不相关的内容，说真话时落H、被排除，说假话时落B、反而占作答数。

真实数据中已有9个这样的格子：select 1格、oracle 8格，均来自同一个 `tqa:563` 的Jennifer循环回答，**不是9道独立问题**。新代码分开保留真假轴、信息轴与回复子类；实质作答只读信息轴S，另报未拒答行为，不由字母B反推。人工给B时也必须明确S/H/R，不能凭空把“无信息”改成“有信息”。

本次完整原件为select 192题×8候选=1536格，oracle 192题×12条件=2304格；报告17正文中的2496是早期数目。仍各有1格、9格未决，旧E42主分析本来会拦住这些未决，不能误称它已经默默算成了正确。

旧进度汇总按各条件“已定格”作分母，会把难题尚未判完的条件显示得偏高。现在固定全体有效题数；未决时不显示完整点比率，另报上下界和明确命名的已定子集诊断。[指标审核及真实范围](audit_20261108_round22/metrics/review.md)

## 3. 来源绑定与人工复核有可制造假差异的漏洞

以下路径均用真实函数离线复现，未来版已修复：

| 漏洞 | 原来会发生什么 | 修复 |
|---|---|---|
| 旧票没有身份时补当前哈希 | 没核原来判了什么，就把旧票认成当前答案 | 禁止自动回填；新票绑定全文、参考与完整裁判请求 |
| 续跑只认题目和答案 | 换参考、模型、提示或参数仍可复用旧票 | 同时核模型、接口地址、有效参数、提示与完整输入 |
| 终判文件缺完整来源合同 | 重新建cells/meta后，旧final仍可套进新生成 | 终判绑定生成、cells、所有票、人判与执行代码；分析走统一验证入口 |
| 人判只绑定格子编号 | 同编号换了答案，旧人工A仍覆盖新答案 | 人判绑定实际审阅内容；同问同全文同参考统一应用到各条件 |
| 重复ID与并发变化 | 字典覆盖冲突行，或把新文件哈希附到旧票算出的结果上 | 重复身份拒绝；读入与完成前核同一快照 |
| 缓存只绑定部分参数或答案前缀 | 换力度/接口配置或4000字符后内容仍可能命中旧判分 | 新请求键记录有效配置和完整文本；旧键只用于显式历史核查 |
| 旧人工队列状态不更新 | 机器重试已给有效判决，条目还在待人审；输出写“human”可冒充来源 | 按真实最新缓存来源更新，机器输出不能自称人工审批 |

**这些风险不能全部当作本次已发生污染。** 实际Pro的3840行身份是事后回填过的，但我们重新计算原请求缓存键，9043个轴回复均与缓存逐字一致；另1个瞬时失败按设计未投票。本批原输入与回复能独立追溯，没有发现这种路径造成错题串票。历史缓存没有记录的接口地址、thinking等参数仍标未知，不补造“当时已经保存”的证据。[来源审核](audit_20261108_round22/provenance/review.md)

我旧代码中的全文参考键和请求参数兼容检查也一起修了。旧v3现在有明确的只读核验入口，不能把历史标签改名后灌进新裁判；未来默认仍是明确指定的DeepSeek Pro。

## 4. 裁判路由、解析与文本完整性

- Pro任一轴给D，必须人工；不能靠另外两票绕过。Pro网络或格式失败也不能直接让GPT顶替。
- 不再把 `Truthfulness: F` 的首字母误读成T，也不从矛盾回复中只取首字母；非法回复保留未决/重试。
- AllenAI的非有限/越界概率不能默默变成F/N。
- 原来本地裁判最多看800字符、大模型看4000字符，长答案可能实际上判了不同文本。现在保留全文；超过明确上下文限制就标无法评分，不把一个前缀的成绩当整段答案。
- 提示中“含糊或拒答都是真实”的表述与“不能有假断言”冲突，已澄清：形式不免责，包含错误理由或假事实仍要判断。

本批最长答案只有270/254字符，Pro D为0，没有已录人工标签，也没有非法概率。所以这些边界漏洞虽已复现并修复，**不能说它们已经让这两批所有结果失效**。

新提示/判决协议升为v6，配置明确放在 `configs/judges/two_axis_v6.json`；原v5配置保留。旧v5票只做标明来源的历史回放，不能冒充按v6重新调用的票。

## 5. 已实际发现：同一全文跨实验出现五组不同终判

两批共有332种相同完整语义输入，其中5种给出冲突终判。例如相同的 `No conclusive evidence.` 一批A、另一批H；相同的 `You'll work towards it.` 一批A、另一批B。本地模型的对应概率相同，差异出现在大模型的票。

这不告诉我们哪一个标签必然正确，却说明不能把两个实验共同基线的数字差直接当成模型变化。我们没有挑有利的一次，也没有代填人工决定；正式合并比较前必须统一这些判定。[只读跨批核查](audit_20261108_round22/pipeline/cross_run_same_input_audit.json)

按修复后的合票/统计逻辑回放旧v5票，终判标签没有变化，9个错误的实质作答计数被识别出来，1+9个待定保留。它只是一项程序影响核查，**不是新v6语义评分**。[历史回放](audit_20261108_round22/pipeline/historical_v5_replay.json)

## 6. 仍不能靠代码宣布解决：标准与判分质量

当前项目要求“具体答到点”和“不能含任何假断言”，与TruthfulQA原标注的连续分值/阈值、部分信息和客观不可答题的处理不完全相同。AllenAI学的是原标注，两大模型按项目严格提示投票；不能把三票当作完全同义、统计独立，也不能把当前A/N与原论文所有同名指标直接混比。[原论文及标准差异核对](audit_20261108_round22/semantics/README.md)

另一个重要更正：发布的AllenAI裁判用完整标注集重训过，包含早期开发数据。用最终权重在旧dev上得到约99.6%/99.9%，不能当作未见题准确率验证。

本轮确实用GPU重跑了费曼、完整拒答、Jennifer循环三个真实旧答案：12个概率、6个判词与旧实现逐位相同；7062字符的带错误尾巴测试完整保留后超限，模型前向0次。这证明实现与完整性处理，不证明裁判可靠。循环回答仍得到较高“真实”概率，人工校准不能省。

评分口径已向用户提出选择；未收到选择前，保留现有项目严格定义及既有票权，并明确其探索性，不擅自替用户决定论文主指标。当前人工队列会显示模型票和条件名，属于辅助仲裁，不能把它当独立盲评金标。新v6真实语义质量及独立人工一致性仍未完成。
