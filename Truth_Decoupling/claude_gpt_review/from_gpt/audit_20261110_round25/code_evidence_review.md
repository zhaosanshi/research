## 1. P1：64%/96%不是整层状态交换的结果

方案21第25–26行把两个E42控制臂称为“整层状态换成真实来源”和“金标状态写入”；第34行据此推断“一条方向装不下一个答案”，第98行打算作为整层来源交换上界复用。这一前提不成立。

实际代码链：

- `from_claude/code/scripts/e42_qa_oracle_and_select.py:266`的`truthful_source_only`和`:268`的`gold_source_only`都调用`decode(..., mode='source_only')`。
- `from_claude/code/core/qa_source_interchange.py:201`附近的`next_logits()`，`source_only`直接取来源提示的模型输出。只在`mode='source_interchange'`分支注册`capture_source`和`write_base`；`source_only`连base模型前向都不执行。
- 所以两个控制分别是“直接使用如实提示生成”和“直接使用包含金标的提示生成”，不是在某层把整个隐藏向量移入普通提示。

实际调用生产函数的CPU复现：来源提示前向1次、基线前向0次、写入0次；捕获/写入函数被设为一旦调用就报错，执行仍通过。旧E42原件也精确对应：192题中如实提示未改70题、金标提示未改8题；这两个臂全部192条的`write_over_base_mean`与`write_over_base_max`都是0。

**应改为提示控制，不得据此声称已有整层交换上界或证明秩1容量不足。** 若最小版不想增加实验，直接撤销该因果推断即可，不要求现在补一轮整层交换。

证据：`code_evidence_reproduction.json`；原件SHA256为`bad8308887be1cfe183dbbf9c9185bd33ce3e808ba7b703779514f082d04b3d3`（R24只读E42快照中的`oracle-tune-j6/tune.json`）。

## 2. P2：相同问题前缀零差，不能当作旧E25实际交换零差

方案第34行的条件命题是对的：同一问题、相同提示，在答案之前的因果状态相同，交换该位置没有输入差异。但**旧E25不是在这里读写**：

- `core/qa_das.py:104`至`:111`：`answer_end = len(encoded['full_ids']) - 1`，是答案最后一个词元；之后再接自检提示，`label_predictor`更晚。
- `core/qa_das.py:188`至`:190`：`_source_states()`捕获`item['answer_end']`，此时正确答案和错误答案已进入上下文。
- `core/qa_das.py:270`至`:272`：训练自检损失也在`answer_end`写入，不是在问题末词写入。

用现有CPU因果网络测试夹具执行真实`prepare_selfcheck_pairs()`和`_source_states()`：同题问题末态差为0，真正答案末态差约3.826；问题末位置65，正确/错误答案末位置分别70/73，自检预测位置101/104。

这说明旧训练确实发生了非零、答案条件化的交换。**合理怀疑的是“答案已给出后的判决训练”与“答案尚未生成时的使用”不匹配，不能写成已查明旧训练交换的两边一样、因此等于没换。** 这是支持重配训练目标/来源的动机，不是已定位唯一失败根因。

## 3. §5哪些能复用，哪些必须真正重写

| 部分 | 原函数核验 | 对方案的最小要求 |
|---|---|---|
| `_interchange_hook_factory(positions='all')` | 确实把同一个来源子空间坐标写入当前前向的全部位置 | 可以复用；来源应保存隐藏状态，在当前可学习w下投影，不能训练开始前就固定一个脱离w的坐标 |
| `SteerSpec(mode='clamp', position='all', alpha=1)` | 数学上与上述训练写法一致；提示的全部位置与后续单词元解码前向都会作用 | 可以复用；β调目标坐标，不能误传成alpha=-1（后者是反向外推，非钳到另一目标） |
| `train_das(loss='ce', positions='all')` | **当前明确拒绝**，报`loss="ce" supports positions="last" only`，并把CE路径T强制为1 | 不是改配置即可；需新增整答案损失/目标序列分支，保留原TF标签CE含义 |
| `gold_label_ce_loss()` | 对标签首词元候选集合求概率和，只评提示末位一次 | 不能把答案token列表直接当它的`target_ids`；那会求“任一答案词的概率”，不是顺序预测整答案 |
| `multistep_kl_loss()` | 多步序列循环可参考，但调用的是源模型分布KL/JSD；默认`anchor='current'`会随答案移动来源读位 | 新CE须明确目标`y[t]`、输入仅含`y[:t]`、来源读位始终为原提示末位；不能只换函数名或忘设锚点 |
| C反向目标 | 推理方案写的是反射目标`2*mean(z_x)-mean(z_C)`，训练反向来源却是每题`z_x` | 需明确两者不同；不能用同一个“β=-1”名称掩盖训练/推理不同的目标 |

CPU数值验收已执行：三位置隐藏向量沿单位w写到7；训练hook与推理clamp逐值相等，正交部分不变；下一次单词元解码也被写到7，共两次hook应用。

其余实现要点只需在最小验收里明确：答案损失的预测位置比目标词元早一位；24词元截断的样本不能称“完整答案训练”，须记录完整覆盖与截断；先核一对样本的读位/写位/目标位，再批量。这里不要求新建额外大框架。
