# 来源交换式生成DAS：最小设计审计

**结论：可以进入三题级实现验收，设计本身没有必然的目标泄漏；它确实使用外部来源状态交换，不再是E27的固定中心放大。尚不能把“准确／错误指令”直接称为已识别的普适真假因果变量。当前只审设计，不启动训练。**

## 1. 方法身份成立的条件

写入必须严格是`h′=h+W Wᵀ(h_source−h)`，W保持单位正交、力度固定1。每个来源状态都由未干预的同一冻结模型计算，并停止来源分支的梯度；只在base分支注册写入。不能让共用模型上的hook顺手也改了source，不能把来源状态替换成可学习的`Wh+b`，也不能另做内容放大微调。

这使部署后的被交换坐标满足`Wᵀh′=Wᵀh_source`，正交补上的分量不变；两项都应在三题验收里测，比仅检查改动范数更能抓住写错位置、错源或没有实际写入的问题。

## 2. 需要钉住的五个实现点

1. **“同一prefix”必须是同一串答案词元ID。** base/source分别构造提示，随后追加完全相同的已知答案前缀ID；不要把解码文本重新分词后当同一前缀。训练第t个目标读写各自`P−1+t`，批量左填充时另加各行填充偏移。不同长度的提示不能共用一个物理索引。
2. **来源只看过去。** 即使训练用整段教师强制前向，也必须严格因果；保持当前前缀，用同长度替换源序列从当前目标起的未来词，验证当前来源状态不变；比较当前损失时，目标标签本身保持不变。训练给参考答案的过去词是正常监督，测试给未生成的参考词才是泄漏。
3. **两套缓存独立。** source先前向取状态，base再交换并选下一词；这个base选出的同一词追加两流。每流维护自己的提示长度、位置与缓存，source不能先生成自己的另一个词。不要依赖两次`generate()`内部共用的隐式缓存。
4. **正负各半按分支平均损失实现。** 正支、负支分别对自己的目标词求平均，再各乘0.5。不能把两串拼成一个总平均，否则更长的错误答案会取得更大权重。
5. **先冻结词元、提示、W和算子身份。** T／F指令在训练与部署间保持固定；source-only和混合对照使用同一T提示、相同底座精度与生成预算。三题中另用相同base/source输入做零交换检查即可，不增加正式方法网格。

## 3. “改动不超过源差”需要分清理想值与低精度写回

在精确算术下，`||W Wᵀ(s−h)||≤||s−h||`正确。但实际低精度写回可能超过这个界，不能把它一律诊断为交换错误。

已执行的BF16小反例：base=[1.0078125,1.0078125]，source=[1.015625,1.0078125]，W=(1,1)/√2。源差范数0.0078125，理想投影范数0.00552427；写回舍入后两维均变化0.0078125，实际改动范数0.01104854。

最短修法：在高精度理想投影上检查范数界与坐标交换；另记录实际写回、舍入误差和相对残差改动。实际坐标比较使用与低精度分辨率相符的容差，不靠任意放宽阈值掩盖错误。

## 4. 对照足以回答什么

原模型、T提示单用、等权双前向混合、冻结随机W交换、训练W交换，足以初步区分“提示本来有效”“多算一次有效”“随便换一维”和“学到的交换子空间有效”。不需要此时加模型、加EOS或再开一批方法。

“等权logit混合”应写死为`argmax((logits_base+logits_sourceT)/2)`，两个流均消费该控制自己选出的同一前缀；它等价于几何概率混合，不是两个概率分布的算术平均。不要实现一种、文字写另一种。source-only则自然消费自己的生成前缀，作为直接可用的提示基线。

这些对照不能自动证明优于所有已有低秩微调方法，也不能保证不产生乱码；它们能检验这条来源交换方案是否值得继续。

## 5. 高层变量与负支的解释边界

高层变量是“来源执行哪一种指令策略”，不是已验证的“来源确实知道真相”。T源不一定答对，F源也不一定产生指定的那个错误答案；多个错误答案都可能满足F指令。指定金标作为训练目标可以做，但这时学到的是让指令来源交换支持指定目标的子空间，不能宣称天然忠实于source原本行为的因果抽象。

三题验收中直接记录源自身对目标词的概率和源单用的输出，就能看清这层差别；不要用金标答案选择测试来源，也不要让F提示带入该题具体错误答案。正支教师强制成功仍需真实生成验证，因为部署前缀可能已偏离参考答案。

**可继续条件是三题实现检查成立且原始输出值得进一步看；这份设计审计不提前承诺正收益或乱码消失。**
