## QA-DAS 读出反号：有实际数据证明

DAS（分布式对齐搜索 · 用内部表示交换估计方向）里的“轴”与其负号表示同一条轴；用 `w wᵀ` 交换坐标时正负号抵消。但把 `h·w` 当作分数挑最高答案时，正负号决定挑哪一端。

原代码只把 TF-DASCE 对齐到 TF 训练均值差，却原样读取 QA-DAS。实际三个 QA-DAS 方向的文件指纹与所审 raw 完全一致；对应 TF 真减假训练均值方向的点积为：

| 层 | 点积 |
|---|---:|
| 28 | −0.0561153016 |
| 29 | −0.0472021851 |
| 30 | −0.0510939798 |

同一 QA 银行指纹、每层方向指纹均已核对。还在服务器验证了**当前 TF calib＋dev 的文本、标签、顺序和 TF 提示，与保留方向银行的来源哈希一致**；训练问题与本次 192 题不重叠。

未来 select 路径现在对两族方向都按该训练均值差定号；近零点积标为 `orientation_uninformative`，不硬称朝“真”的方向，也不进入坐标选择。oracle 路径没有训练定号参数时保持原轴；实际解码器测试确认 ±w 的交换写入输出一致。

## 无 gold 的部署接口与启发式边界

原 select 调用会构造根本不用的 gold 提示，所以缺参考答案的问题会报错。它**没有把 gold 提示实际喂进已有 select 模型分支**；这是接口依赖，不能写成已证实的标签泄漏。

未来 select 只构造实际使用的 base / truthful 两个提示。用服务器原分词器，把 192 个真实问题的 gold 完全移除并禁止读取参考字段后，两个提示的所有词元 ID 都与旧 raw 完全相同；没有加载模型、使用 GPU 或调用接口。oracle 仍必须有 gold。证据：`real_tokenizer_nogold_check.json`。

旧词面拒答过滤仅发现一格被标拒答却为旧 v5 A：`tqa:484` 的回答是 “I don't know. There's no such thing as a completely risk-free investment.”。但该题八个候选都被标记，代码回退到全候选池，A 并未真正被排除；verdict 与 TF-DASCE 也确实选到了它。**实际被排除的旧 A 为 0**。没有把带判分信息的语义过滤偷偷塞进选择器；只能把它称作词面启发式，不能保证精确识别拒答。
