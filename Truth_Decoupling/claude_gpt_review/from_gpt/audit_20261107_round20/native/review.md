# 原生 C 门控：独立复算与结果解释

**C 确实能大幅改变实际交付量；但当前这层 C 仍没有让组合稳定胜过同份额的 E＋简单筛题。** 这修正了“C 的实际作用只能几个百分点”的旧说法，没有救回老师的组合贡献。全部结果只来自已反复使用的 192 道调参题，属于探索性诊断。

独立脚本不导入生产评分/配额函数，从归档原文与判分记录重建交付：236 个原生条件、1416 个同实际数量对照全部一致；所有交付ID也逐项一致。核对了源数据哈希、完整题集、判分来源、同题同答案同判分、两种写入范围共用门控分数，以及只改门控时答案原文确实固定。此核查不等于人工确认每一道外部裁判事实判断都正确。

**在线门控与离线计数分开。** 模型可以在线只根据 Yes−No > 0 发出候选，候选本身也可能是模型的拒答。本文的实际实质作答率由看过参考答案的外部语义裁判标注后统计；同 K 筛题对照也借用这些“是否实质回答”的离线标注。正确 A/错误 B 不参与排序，一律可选；只排除未尝试 C。因此这些表不是“线上无需任何裁判、一定精确填满 K”的部署证明，也没有证据据此把主表说成按答对挑题。

**随后完成的标注修复**：下面数字与图忠实呈现原 v3 标注。另发现 Qwen `tqa:101` 的完整个人拒答被标成 A；59 个条件里共 47 条重复记录受影响，Llama 为零。已按同一个高精度守卫给所有组生成修正侧表，并按修正后的实际 K 重筛对照，见[守卫审计](../refusal_guard/README.md)和 `../refusal_guard/sidecars/native_*`。原件未改，不能把“原始复算一致”称为所有语义标签都正确。

## 一、真正接上交付后，C 不是动不了

只改门控、保持原模型候选不变时，C 从 −2 到 +2：Llama 自由问答交付从 2/192 到 164/192；Qwen 从 0/192 到 117/192。真假判断分别从 0/384 到 308/384、0/384 到 384/384。所以“问答曲线必然很短”不成立：之前只看把门控方向移到另一套答案提示后，模型自己拒答变了多少，并没有让 Yes/No 真正决定交付。

这说明 C 是可用的数量控制旋钮；**数量能变不等于挑得更准。** 门控仍可能放行错题、拒掉对题。

## 三、给 C 公平机会了吗

比旧表公平了一步：门控已真正接入交付，E 固定，剂量双向扫，两种提示范围拆开，简单筛题对照也对齐实际数量。但是仍只用了按读出相关性选中的一个 C 层。读得最准的层未必是写入后最有用的层。

也不能把四个设置都说成“只挑了末层”：Llama 真假判断 C 在 26/32 层，自由问答在 18/32 层；Qwen 分别在 30/36、31/36 层，层号均从零计。Llama 问答已在中段。

下一最短检验是固定 E、原候选和指标，预先选模型深度 25%/50%/75% 以及现有 C 层，使用每层自己估出的方向与尺度，只改变 C 所在层，先扫 ±1 并保留零干预对照。先三题检查真实写入和分词，再完整 192 题；保存所有点，不再按可读相关性直接宣布赢家。若先只做门控提示写入，应明确它没有扫描答案提示中的 C 写入层。所有层选择仍是探索，不能把这批题上挑出的最大值当未见数据结果。
