# Claude 15：R19 复现脚本失败传播与完整性修复

**修复未来运行的核验与启动代码，不改历史数据、模型调用、实验参数或旧比较报告。**

| 文件 | 确认的问题 | 修复 |
|---|---|---|
| `r19_compare_outputs.py` | 先转 ID 字典会静默覆盖重复行；只比较输出/结束标记，漏掉题文、已保存的词元与其他逐题证据 | 先验证唯一 ID、完整行数/条件/完成状态，再比较顺序与全部逐题字段；核题文和已保存词元、关联 context 文件哈希。拒绝重复 JSON 键与非有限数 |
| `r19_random_init_check.py` | 显示 `exact False` 仍退出成功；不受限的反序列化 | 不匹配退出 1，坏输入退出 2；仅允许 `weights_only=True`，不回退到可执行任意对象的加载方式 |
| `r19_angle_check.py` | 零向量及非有限数可被余弦默认值/夹取掩盖，误报正常角度 | 验证方向维数、有限性、非零与层集合；先按最大值缩放再计算夹角，坏数据非零退出 |
| `r19_compare_adapters.py` | 同样存在不受限加载；差异只打印、不反映到退出码 | 受限加载并拒绝坏张量；缺失/形状/数值差异退出 1；描述性用途可明确加 `--report-only`，仍显示不一致 |
| 三个 `r19_reproduce*.sh` | `echo $?` 后函数返回写文件成功；裸 `wait` 没有逐个核对 PID，失败也写 DONE | 保留每个子任务真实退出码；逐 PID 等完全部任务，任一失败整个驱动失败，只写 FAILED，不写 DONE |

共用校验在 `r19_validation.py`，共用启动逻辑在 `r19_run_common.sh`。启动器要求显式 `CODE_PATH` 与新 `RESULTS_PATH`，拒绝覆盖既有日志、退出码和完成标记；缓存改用 `HF_HOME`，不再重设用户 HOME。模型、层、题目、力度及“只生成不训练/不判分”的命令参数没有改变。

## 缺失证据不能伪造

实际查看了 R19 原始归档：

- random controls 的 `prompt_token_ids` 和 `generation_token_ids` 都是逐臂字典；新校验在真实文件上通过。
- generation dose 有逐臂 `raw_token_ids`，没有保存提示词元；后者明确列为未保存。
- pure DAS 的试点、完整结果及其 context 文件都没有保存输出词元。不能从原文相同反推词元相同。

比较器默认将缺少输出词元证据视为不完整，退出 2。历史核查可显式加 `--allow-missing-token-evidence`；此时最多得到“已保存字段一致”，`all_identical` 仍为 false，不声称缺失词元已经复现。既有 top-level 来源差异仍会报告并导致不一致——旧脚本原本也如此；来源/记录不同不等于已经证明模型回答不同。

## 已实际验证

16 项回归通过，均包含真实执行路径：

- 三个启动脚本分别让每一个子任务位置退出 7，确认父进程非零退出、逐个等待其他子进程完成、各 `.exit` 保留原值、没有假 DONE；成功路径和拒绝覆盖旧证据也通过。使用了本机真实 `/bin/bash`，并修正其旧版本对空数组与 `set -u` 的兼容问题。
- CLI 实测重复 ID、改题文但原文相同、改输入/输出词元、缺臂、共同缺行、未完成、重复 JSON 键、坏 context 哈希、NaN/无穷/零向量均被拒绝。
- 构造只会写临时标记的可执行 pickle 元数据；受限加载失败，标记没有生成。
- 7 份真实 R19 generation 文件通过结构验证与自身完整字段比较；缺失词元照实标记。26 个真实旧/发布版 adapter 经受限加载成功，方向有限且角度可算。

证据：`tests.log`、`historical_artifact_validation.json`、`restricted_real_checkpoint_validation.json`。真实归档核验是结构/加载兼容验证，不冒充重新执行 GPU，也不冒充把未发布的两套完整运行重新逐词元对齐。历史 Llama 均值差张量差异等已有事实没有被改写。
