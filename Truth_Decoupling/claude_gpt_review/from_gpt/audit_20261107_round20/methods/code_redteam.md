# 第 20 轮新增测法的独立代码红队

这份记录审实现与可执行性，不评价尚未结束的真实模型效应。审阅对象由主代理编写，本文件由独立方法审核代理完成。

## 原生 C 门控：`e28_native_commitment.py`

核心规则正确：固定 E，首词 Yes−No 大于零才允许交付，同时排除模型自身的实质拒答；比较对照必须交付完全相同题数。只用调参集，不冒充新的测试集；只改门控与同时改门控/答案两种范围分别报告。固定配额主表保留。

红队发现并修复：

1. 原先用 `zip` 合并答案与门控分数，仅检查答案侧 ID；门控侧错序可把别题分数配到当前答案。现严格比较两侧完整 ID/group/顺序与长度。
2. 原先判分和报告未核对完整条件、完整题目集合，删行可能改变分母。现按冻结声明重建所有条件与固定题集，完整报告缺一行即拒绝。
3. 原先允许 `outcome` 与 `grade.label` 不一致进入报告。现核对派生 QA 标签、原始输出/分数、真假陈述固定标签与题组，未知判分不出表。
4. 现绑定源数据哈希、原始生成哈希、裁判配置与名称/版本；误用另一个来源目录或改动已判分原文会报错。
5. 原先 `%g` 六位有效数字会把两个邻近剂量命名为同一条件。现用可往返表示，避免覆盖。

`from_gpt/test_native_commitment_20261107.py`：13 项通过，包括小型真实因果网络的收集→判分→报告、复用旧条件、零剂量、新剂量、两种范围，以及同 K 无足够回答、零回答、拒答不能填额、固定 58/100 配额、错序/删行/改标签等边界。新增验证把所有 A/B 对错标签互换、C 拒答标签固定，选择 ID 完全不变；这明确了离线实质回答资格与按正确性挑题的区别。

真实批量判分还暴露了逐条重写十几 MB 文件的性能问题。未来版改为每 64 条或 5 秒保存一次，异常与完成出口必保存；外部裁判响应本身仍逐次缓存，判分口径不变。执行测试模拟第 10 条后 API 中断，检查十条进度落盘，恢复只判余下条目，且保存次数显著少于判分条数。

## E+C 配简单筛题：`e26_joint_simple_extension.py`

审核重点：旧 E26 测试只保存原冻结条件；新增 E+C 简单筛题可能选中旧测试未运行的条件，不能把不存在的结果当零，也不能直接从测试结果挑最好的条件。实现按已冻结调参清单只补缺失条件，单独目录，明确为旧测试曝光后的探索性补全；原始主分析族不变。

红队修复：拒绝重复条件定义；验证恢复运行的题目组、顺序、完整/部分状态、有限分数、真假陈述预测与固定标签；传入模型也核对原分词记录；判分恢复同时核对原始元数据和生成哈希。

`from_gpt/test_joint_simple_extension_20261107.py`：6 项通过。用真实小网络执行生成和判分；另外独立验调参选择清单，篡改选择即拒绝；判分元数据改错即拒绝；执行后原 E26 文件哈希不变。组件执行测试会直接提供有效 E+C 算子来覆盖新前向，不将这个测试夹具伪装成研究实验。

## E26 主流程来源绑定及未来代码身份

来源绑定新补丁最初只核扫描清单列出的文件，仍有一个实质遗漏：实际方向加载器会把目录内同层、同版本的额外种子一起平均。只记录更多文件哈希不够，必须保证选层扫描与部署实际消费的是同一文件集合。

已修成直接询问真实 `load_das_direction` 的 `files` 返回值，逐层与扫描声明精确比对，并核完整部署层集合。测试使用真实可读取的方向检查点：加入第二个合法种子后，实际加载方向确实变化，新检查明确拒绝；不被加载的其他秩或其他版本文件不会误报。`test_round20_sources_20261107.py` 共 5 项通过。

服务器独立目录验证：Llama 32 层/32 文件、Qwen 36 层/36 文件通过；既有 E26 方向库中对应 32/36 个冻结 E 向量与当前检查点逐层一致。复制到临时目录并加有效新种子，方向变化约 0.005，两个模型均被拒绝；生产 E1 文件前后哈希相同。代码与完整记录见 `server_source_check.py/json`。旧扫描未记录历史哈希这一局限仍保留，不补造历史记录。

这次服务器源验证实际使用的完整代码在 `evidence/server_source_validation_runtime.tar.gz`，对应清单验证入口哈希与结果记录一致。它是完成后的代码快照，不伪称事前承诺；后续本地文案和新增元数据变更没有覆盖这个运行版本。

E28/补全脚本最初只记录入口哈希，未覆盖实际生成依赖。未来版使用新增 `core/experiment_provenance.py`，记录全部核心模块及 E25/E26/E27 等实际依赖入口，启动与完成前重新核对。`test_experiment_provenance_20261107.py` 的 3 项测试通过：入口未变而依赖被改、添加核心文件、缺失依赖均能检出。**没有热更新正在运行的服务器版本**；本轮已启动运行的来源证据由当时完整代码目录的事后快照提供，不能把事后快照说成事前哈希承诺。

上述四个本轮测试文件共 27 项通过。

## 真实来源交换：`qa_source_interchange.py` 与 `e29_qa_source_interchange.py`

只读红队，没有修改该代理拥有的代码。核对了真实源先计算且无基础流写入钩子、单位方向交换公式、源/基各自提示长度、共享实际生成词元、独立缓存，以及无缓存参照重做全部历史预测位置。未发现这些路径的逻辑错误。

提出两项补验：真实模型同源/基提示时应与原模型恒等；如果缓存表示无法提取键值张量，不能把空集合“互不相交”记作已经验证缓存独立。实际模型的缓存/全序列低精度差异必须先与原模型对照、再用高精度核验，不能未查数据就判定错误，也不能单纯放宽阈值掩盖错误。具体真实机器验证与最终处理见 E27/E29 证据目录。

## 新来源交换训练与跨层门控

`qa_source_interchange_training.py` / `e30_qa_source_interchange_train.py`：只读逐行红队确认，训练专用算子保留 w 在投影和写回两处的梯度；来源停止梯度且先无干预前向，基础流与来源流各自按 `P−1+t` 和填充偏移读取同一答案前缀位置。损失先按每题有效词数平均，训练仅来自原估计题。没有固定中心、外推或额外结束符。底座通过冻结上下文保留参数和训练状态；实际前向每次把原始参数归一化，最终也只存单位方向。它与旧 E27 算子不同，不能因为都只训练一条方向就猜成同一方法。

红队指出 E29 来源提示/编码函数也是训练与部署依赖，旧来源身份函数没有包含该入口；实现代理已把 E29/E30 入口纳入完整源码身份，增加结束前校验及训练快照核对。实际执行与效果另见来源交换训练证据；仅通过这些机制检查不能保证回答变正确。

`e31_causal_gate_layers.py`：预先给定 25%/50%/75% 深度加旧可读层；使用各层自己的 C、保留缺失层记录，固定 E 与原候选答案。门控前向收到的字段不含金标、答案或判分。红队补充要求已实现：完整协议/模型/任务身份验证，原生每个点按精确实际 K 加原模型/固定 E 的两种筛题对照，完整运行对照分数还须重现旧批次记录。只扫描门控提示写入层，不声称已扫描答案提示中的 C。独立执行其 9 项测试通过。

对 E+C 同简单筛题扩展，另从原始记录独立重排三个代表格并核全部选中 ID：Llama 真假 50% 为 E 457、组合 451（K=529）；Llama 问答为 100、104（K=261）；Qwen 问答为 118、119（K=261）。与报告一致。本次代表格红队没有重新跑该报告全部 2000 次重抽样，不能替代 E26 审核代理的完整统计复算。

## E32：来源生成组的同实际覆盖率补评

`e32_source_matched_coverage.py` 使用相同未干预模型，对每个生成答案算不含结束符的平均词对数概率；只把问题与生成文本送入打分前向。同问同文只算一次，所有五/六组一视同仁，再按同一批参考知情的离线实质回答标注做固定配额比较，A/B 不参与排序。原始生成与判分文件不变。

红队修正三个身份缺口：报告须核评分模型和完整来源，不能只认生成文件哈希；判分须核逐条规则版本、参考、问题与完整条件；输入只接受合法 E29 五组/E30 六组及无参考生成声明。完成或续跑评分文件也检查有限值、完整条件和同文同分。

`test_source_matched_coverage_20261107.py` 7 项通过，包含三题真实小网络打分→出表、去重前向次数、送入模型的字段、重复执行免重算、原文件哈希不变，以及错模型/来源、旧判分规则、错参考、同文异分/异判、缺题与错误提示词元的拒绝路径。加上前述四个根测试文件，本审核代理新增/加固的根测试共 34 项。
