# 来源里不再提供当前题目内容：同训练对照

此对照回应 Claude 第 15 份审核中的具体缺口：有监督训练本身可能提高成绩，不能把训练后来源交换的收益全部归给来源内容。这里不是换一个向量就算完成，也没有让来源等于基础状态而人为得到零梯度。

固定原 E34 的 Llama 第 15 层、Qwen 第 17 层、原始 DAS 初值、92 对题×3轮、配对损失、学习率、优化器、力度1和48词元预算。仅将**来源提示里当前问题所占词元的注意力键屏蔽**，然后重新学习单位方向。基础模型仍完整看到原问题，来源的系统指令、角色、提示长度、原位置与已生成的共同答案前缀都保留。因此准确名称是“无额外当前题目内容的来源”，不能简称“完全没有任何信息”。

## 核心实现与验收

- 用真实聊天模板中的单次占位标记定位问题字符段，再由 Hugging Face 快速分词器的偏移映射定位词元；核对词元 ID 与实际来源提示完全一致。系统提示里即使出现同一句问题也不屏蔽。跨词元边界只容许附带空白，不容许误屏蔽角色或其他实质文本。
- 训练仍调用原 E34 的损失和训练函数。限定作用域的前置钩子只识别已声明的完整来源前缀，替换其注意力掩码；基础/参考前缀原样通过，未知或歧义前缀报错。正答案、负答案与共享前缀三条来源路径都覆盖。位置编号先按原未屏蔽提示计算，再仅替换注意力掩码，绝不因中间出现空洞而压缩位置。
- 推理用独立解码子类，仅来源前向应用同一掩码，并在每一步缓存解码继续保留问题空洞；公共答案前缀始终可见。未传掩码时直接复用原前向路径。
- 两个真实模型都先做3训练对、3题生成。相同长度替换被屏蔽的题目词元后，来源预测位置状态和输出分数逐位相同；三个缓存步骤也逐位相同。基础题目词元改掉则分数明显改变，证明基础分支确实仍能读题。未传掩码与原算子三个步骤逐位一致。
- 新方向再次做相同硬检查；来源没有梯度，只有单位方向训练，三对试点均为3次非零更新。没有结束符补丁、文本截断修补或金标推理输入。

原 E34 继承的“来源=基础时为恒等”检查，在这里仍是**未屏蔽的退化算子检查**：诊断复制出的两个基础前缀都原样通过。它不声称“相同词元但只屏蔽来源问题仍为恒等”。新的无内容证明是上面的真实屏蔽词元替换不变性。

代码：`core/qa_source_question_mask.py`、`core/qa_source_masked_preference.py`；入口 `scripts/review_checks/qa_masked_source_control.py`。原 E34 配对损失和原来源交换文件未改。七项本地执行检查使用真实快速分词偏移及小型因果注意力网络，覆盖双缓存、位置、三条训练路径、无掩码逐位兼容、原权重不变、实际三次优化和检查点往返，以及生成时父七臂内容/新权重身份；另有原算子7项和原配对目标6项通过。实机检查用于补足小网络不能代表真实模型这一限制。

## 产物身份

新协议为 `supervised_source_pair_preference_question_mask_v1`，新增第八臂 `pair_preference_question_masked_source`。前七臂来自原 E34，问题、原文、完成标志、生成词元和轨迹逐项继承；原判分单独锁定，守卫仍应统一施加所有方法，不能只修新方法。

来源模式为 `question_attention_keys_masked_positions_preserved_v1`。计划记录原 E34 检查点/清单/生成/判分哈希、原 CE 初值指纹、训练题与顺序、当前代码依赖、问题清单及固定训练参数。模型文件再绑定每题掩码清单与真实不变性证据；新生成的每题另保存实际掩码与词元位置。

服务器使用独立 `review_source_question_mask_v2_codex_20261107` 快照，原 E34 与其他运行未热更新。首版试点的顶层 `training_sha256` 曾继承父字段（其 `identity.adapter_sha256` 一直正确），已修复并用第二版重新跑两模型全部试点；首版原件保留，不能作为正式结果。正式目录为 `results_source_question_mask_codex_20261107/{model}/full92_ep3`，实际训练/生成/判分结果另随完整产物归档。

这是在已暴露调参集上的必要对照，不是新的独立确认。即使有额外题目内容的来源优于这个控制，也不能省略相同实际作答率、强简单筛题和尺度匹配随机控制。

## 已完成的实际结果与交付
