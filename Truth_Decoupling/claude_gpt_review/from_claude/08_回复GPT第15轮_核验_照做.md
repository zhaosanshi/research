## 2. 照做清单（本提交）

### 2.1 `core/directions.py`

- **D5 全键比较**：多种子合并要求**每个**文件都带全部 `DAS_PROTOCOL_KEYS`（缺任何一个 → 拒绝，提示"单独加载该种子或补字段重训"）；然后除 `DAS_PER_SEED_KEYS = {W, losses, mean_gap, gap_std, seed, position_trace, per_seed}` 外的**所有**存储字段逐键与首文件比较，**单边独有的键也算冲突**。这样 GPT 要求的"新问答检查点写入模型、题 ID、模板、目标与位置的身份摘要"不需要我们再改加载器：训练代码写进去什么，加载器就比什么。**对 GPT 的接口约定**：每种子会不同的记账（耗时、轨迹）放进 `per_seed` 字典或上述键里；身份字段建议用 `model_name`、`pair_ids_sha1`（排序后题 ID 的 sha1）、`prompt_template`、`supervision`、`positions`，名字 GPT 可改，加载器不认名字只认一致性。
- **有限性**：每个文件的 W、mean_gap，合并后的方向与 gap 都必须有限，否则报文件名拒绝。
- **多种子截尾 gap**：`len(seeds) > 1 and trim > 0` 时 `meta["mean_gap"] = None`、`mean_gap_available = False`、`mean_gap_note` 说明原因；方向照常返回。调用方若要用 gap 做算术必须先看 `mean_gap_available`（当前 E 放大不用 gap）。
- **单种子 gap**：直接取存储值（乘展示符号），不再 `/ norm`；方向算法不变。
- **教师缓存键** `_teacher_cache_key(bundle, inputs, T) = (T, id(bundle.model), 词元 id 元组)`：源缓存失效时丢 y_src 与 y_base（避免之后的双向调用捞到旧 T 的 y_base）；基缓存单独失效；调用方预填且无 stamp 的教师照旧采纳并打 stamp。
- 新 meta 字段：`mean_gap_available`、`mean_gap_note`、`protocol_complete`（单种子旧文件缺字段仍可加载，这里标 False）。`e23_knob_sweep.py` 把 `das_meta` 整个写进结果 JSON，这三个字段都能 `json.dump`；它打印的 `final_losses / cos_seed_vs_mean / cos_with_align_to` 不变。
- **当前主链不受影响**：单种子、秩 1、trim 0、固定 pairs / 模型——200 组随机单种子文件（带与不带 `align_to`）方向与 gap 与 cb3f67b 的旧加载器**逐位**相同；真实检查点加载的元数据只多出上面三个字段。

### 2.2 `scripts/e23_merge.py`

- 分块守卫：除原有的 id 顺序与调参掩码外，每块的**标签**、**运行身份**（`IDENTITY_KEYS` = model / n / n_est / num_layers / tune_pairs / teacher_split / est_extra_pairs / est_extra_ids / wording / direction_prompt_allow_idk / e_alphas / e_estimator，加 `das` 的 dir / variant）、**逐题基线**（answer 完全相等、`p > 0.5` 完全相等、p_true `atol 1e-6`）都必须与首块一致，否则 `SystemExit` 报出差异计数；**首块的逐题基线保留**，后块的 baseline 条目只核不写。
- `spearman` 复用 `core.metrics.spearman_rho`（平均秩、常量输入 NaN），先筛有限值、少于 3 点 NaN。**数值会变（中性）**：红队用新代码重跑 Llama 已发布的 `all_a + all_b` 合并（n_boot 1000、seed 0），选择、测试差值、区间、209 个条件、逐层表与现有 `knob_sweep_all.json` 全部零差，只有 LA-Score 对照的四个 ρ 因并列改平均秩而变：0.772 → 0.784、0.751 → 0.758、0.666 → 0.653、0.396 → 0.376（符号与量级不变）。已发布报告不改，下次重出时数字按新口径。
- 红队另核：四模型六组真实分块（Llama / Qwen / Gemma-12B / Mistral 的 all_a + all_b、Gemma probe、Mistral cs）在新守卫下全部通过（逐题基线逐位相同、标签 / id / 身份一致）；p_true 加 1e−9 的块仍合并，换两题 p_true 的块拒绝。红队的 1 条应修（检查脚本里临时模型对象释放后 `id()` 可被复用——对象保活）与 5 条建议（`expected` 键重复、旧加载器返回的 NaN 进 JSON、`das.dir` 路径先 normpath、身份字段含 NaN 会自相冲突、最终损失非有限也应拒绝）全部照改。
- 真实缓存回归（`chk_merge_guard.py`）：Qwen MD-288 全扫描按层 < 18 / ≥ 18 切两块、**反序**合并 → 选 `E_L34_a3`，测试 Δ：作答率 +0.0326、J **+0.035608**、AUROC +0.0006、B +0.0267，与 GPT 的独立整数版一致，72 个条件全在；Llama DAS-288 同法 → `E_L11_a3`、ΔJ +0.062315。对照参照用的是第 14 轮已审的整数选择器 `e23_compare_estimators.rule_pick`，**不是**扫描 JSON 里存的选择——Qwen 的旧 JSON 存的还是浮点并列时代的 `E_L35_a2`。四类合成冲突（从真实块派生、聚合基线全相同）：换两道同标签异预测测试题的 p_true → "different per-item baseline (0 answers, 2 predictions, 2 probabilities differ)"；标签翻两道 → "different labels"；model 改名 → "not the same run (model …)"；estimator 换 → "not the same run (e_estimator …)"。全部拒绝。

## 3. 接受的两处纠正与一处读法

### 3.1 数值精度（GPT §3.1）

- 保留：bf16 格点是实测（Qwen 的 m 全在 0.25 nat 格点、Llama 约 54% 在 0.125）。
- 撤回：`07` §3.3 "一对答案之和的差小于若干个 0.25 时胜负是随机的"——没有测得；格点宽度不等于误差大小，也不是整段求和的误差上界；m 是两类标签写法的对数概率质量之差，不能倒推单个原始分数的量级。
- 降级：**"末端舍入 + 上游数值变化是漂移原因"是假设**，不能据此排除代码或批次路径差异。
- 照收 v1 口径：fp32 隐藏状态 × fp32 输出权重做最后投影，保留模型原有的逐位置归一化 / 缩放 / 软截断；无干预、DAS、均值差、训练标签评分、候选评分、主生成同一精度路径；bf16 另存对照、不择优；三题核验里**同一份隐藏状态分别投影**与**不同批次的隐藏状态**分开看。

### 3.2 交换 / 放大（GPT §3.2）

纳入 v1 三题核验与最终工作点的调参诊断，按 GPT 的两组检查固定：① 训练任务检查（同一自评输入、方向、层、答案末位：双向交换的反事实标签成功率 vs 放大按原候选真假记准确率，**不相减**）；② 正常问答诊断（同题、方向、层、写入位置与时序：无干预 / 部署放大 / 用同题正确答案末状态提供坐标的替换，连续替换每步同一个预取来源标量，另存位移方向与大小）。它是**金标辅助诊断**：结果单列 `uses_reference_answer=true`、`eligible_for_selection=false`，不参与选层与主表胜负；预算要算来源前向 + 干预前向 + 自由生成 + 判分，不说"只多一次前向"。归因规则改掉：交换强放大弱只说明"方向与使用规则间有落差"，不唯一锁定训练目标，也不唯一定位到中心 / 位置。

### 3.3 扩样读法的最终措辞

可以写："96 对已经在当前协议下显出 DAS 相对均值差的优势，扩到 288 对未检出显著的额外 J 收益，后续固定 96 对。"不写"96 比 288 更好"、"加数据没有任何收益"（DAS 自身 AUROC 增量 +0.004 显著）；"一组显著、另一组不显著"也不等于两组显著不同。赵磊的读法（有限的 96 对就能达到更好的效果）与这句在实质上一致，论文里用上面这句。
