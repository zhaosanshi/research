### 1.1 为什么身份不变

`core/experiment_provenance.py::implementation_identity` 只哈希 `core/*.py`、`DEPENDENCY_SCRIPTS` 和入口文件（驱动脚本）。新脚本放在 `scripts/` 下，不在这三类里；它 `import` 驱动脚本和 `core`，一个字节不改。它用驱动脚本自己的 `load_source / load_prompts / run_identity / load_frozen / load_direction / verified_base / require_current` 读父实验，身份对不上会在第一次加载时停。自测里有一条：父实验的文件在全部阶段跑完后逐字节未变。

评估用的新提示不进 `systems`（那是身份的一部分），单独放在 `all_systems` 里，只用于渲染。它们的不写入回答由本脚本生成并封存；再次运行必须逐字复现。

### 1.2 臂的写法

```
<基线提示>:<E|C><层>.<种类>.<p|m><力度>[+<E|C><层>.<种类>.<p|m><力度>]
```

| 种类 | 方向 | 每单位力度写多少 | 说明 |
|---|---|---|---|
| `w` | 训练方向 | gap | 直接调驱动脚本的 `arm_write` |
| `md` | 均值差方向 | md_norm | 同上 |
| `rand` | 随机方向 | gap（按存储范数配平） | 同上 |
| `mdg` | 均值差方向 | gap | 第 33 轮要的"同剂量均值差" |
| `wpar` | 均值差方向 | gap × cos | 训练方向那一份里平行于均值差的部分 |
| `wperp` | (w − cos·w_md) 单位化 | gap × ‖w − cos·w_md‖ | 垂直的部分；`wpar + wperp` 恰好等于 `w` 的写入 |

例：`conf:E10.wperp.p2`、`conf_F:E10.w.p2`、`x:E10.w.p2+C31.w.m0.5`。

### 1.3 两层同时写（照第 33 轮第 4 节）

`generate_two` 是 `fd.generate_shift` 的两钩版：两个独立的 `fd.ShiftHook`，各挂在自己的层上，同一张位置掩码、同一条"已结束的行不再写"的规则；不平均、不重新归一化、不跨层正交化；同层两写直接拒绝。C 的方向与 gap 取冻结记录原值——它的输入已被 E 改过，这正是要测的。两个钩子共用一份"哪些行已结束"的记录，并检查两者触发的前向次数相同。每行的 `write` 记成两条（层、写入量、预填位置数、存储范数、解码步数）。

`selfcheck` 阶段在真模型上先验三条退化等价（逐词元）：两写皆零 = 不写入；第二写为零 = 单独第一写；第一写为零 = 单独第二写；外加两钩位置与步数一致、记录的写入量等于计划量。任何一条不满足就报错停。

C 方向可以来自另一个同身份的运行目录（`--c-run-dir`，带它自己的 `--c-e-on / --c-e-off`）：旁支只训了 E，要和主实验的 C 组合时用。

### 1.4 只读状态的检查（`natural`，对应 `32` 第 3 节）

同一道题，两条提示（plus、minus）喂同一段答案词元；取该层在内容段（用户内容第一个词元到序列末尾，即训练时的写入范围）每个位置的状态，右对齐后相减。分三段报告：问题段、读取位置（提示最后一个词元）、答案段；每段给出差在 `w`、`w_md`、垂直分量上的坐标（逐题均值，再对题求均值 / 标准差 / 为正的比例）、差的范数、差的平均方向与各向量的余弦。两条提示的内容段词元不一致就跳过并计数，不硬对。

**内置校验**：在训练题上，读取位置的坐标均值必须复现方向文件里存的 `gap`（容差 2%）；对不上就报错。这同时验证了对齐。

### 1.5 导出

与 `e44_export_judge.py` 同一布局（条件、规格、题目、输出、是否结束、规则弃答），过同一个 `_derive_cells` 检查；只收完整文件，核对身份、冻结文件与方向文件的 sha256。
