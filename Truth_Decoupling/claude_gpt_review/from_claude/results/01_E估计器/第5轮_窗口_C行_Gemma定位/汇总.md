## 0. 一页结论

1. **同分修复**：属实、必要（Gemma 653 句 p_true 并列），但只动了三个第三位小数，第 4 轮结论不变（§1）。

### 2.2 读法

- **Llama：窗口比单层强一倍以上，两种估计器都如此**（DAS +0.060 → +0.149，均值差 +0.055 → +0.129），均值差重现了旧结果（+0.129 对旧 +0.129，逐格一致）。但 J 平手的背后不一样：均值差的 J 增益几乎全是判别力（AUROC +0.072，B 不动），DAS 的 J 增益约三分之一来自阈值偏移（AUROC +0.036，B +0.052）。第 4 轮单层上"DAS 更干净"在窗口上**反过来了**。对论文：积极（工作点成立且可复现）；对"DAS 更干净"的说法：消极。
- **Llama 的 DAS 对窗口位置不挑**：8–13 层范围内 8 个窗口测试 ΔJ 都在 +0.106 到 +0.149，全部可行；均值差只在 11–15 层有效（+0.093 到 +0.140），且 12-13-14 α2、13-14-15 α3、14-15-16 两档因调参作答率漏 +0.031 到 +0.036 被剔。α3 的 DAS 窗口作答率往下漏（−0.04 到 −0.07），所以规则选了 α2。
- **Qwen：叠层就漏作答率**。14 个 DAS 窗口条件在调参集上作答率全部 +0.031 到 +0.109（无一可行），均值差 14 个只有 15-16-17 α2 可行。单层时 L21 起漏、窗口时 15 层起就漏：Qwen 的 E 方向在这些层与"自报知道"纠缠，叠加三层把纠缠放大。规则退回单层，结论不变（DAS 胜）。对 2×2 的 Qwen 行：消极（E 行只能单层、增益小）。
- **Gemma：窗口把事情弄得更糟**。18 个 DAS 窗口条件测试 Δ作答率 −0.04 到 −0.30、ΔAUROC −0.02 到 −0.14；均值差同样。4 个"可行"窗口效果为零。叠层对 Gemma 是放大一个本来就不对的改动。消极，且把 GPT 的"先定位断点"推到最前面（第 3 节）。

## 3. Gemma 定位诊断（GPT 第 5 轮 §5；脚本 `code/scripts/diag_trace_direction.py`，运行 `diag_trace_run.sh`；完整输出 `gemma3-12b/trace_direction_L20_L25.{md,json}`，日志 `logs/diag_trace_direction_L20_L25_gemma3-12b.log`）

### 3.1 做了什么

按 GPT 的设计，用现成的 Gemma 方向（第 20、25 层的 DAS-tf 方向，另加同层均值差方向作对照；中点 cB 与扫描完全相同），在固定顺序取的样本上（第 1 个 DAS 训练对 `tqa:765`，调参集里按测试顺序的前 2 对 `tqa:685`、`tqa:270`）比三种处理：**原样**（零改动走同一个钩子，必须逐位相同）、**交换**（把配对句在该方向上的坐标写进来，α = 1，即 DAS 训练时的操作）、**放大**（扫描用的算子与中点，α = 3）。每次前向记录：实际被改的位置及其 token、|h|、|Δ|、|Δ|/|h|、写回 bfloat16 后保留的比例（kept/Δ）、方向上的投影"改前 → 预期 → 实际"、首词的 P(True)/P(False)/p_true/argmax/top-5、KL(p_参考 ‖ p_干预)（DAS 损失的 t = 0 项）与 KL(p_原 ‖ p_干预)。再把交换与放大在**全部 96 对训练对与全部 192 对调参对**上重复一遍做统计，并与扫描 JSON 里同一调参半的数字对表。

保真检查两项都过：原样处理逐位相同；统计出的调参半基线 J 0.630 / AUROC 0.890 / B 0.518 对扫描的 0.620 / 0.891 / 0.518，`E_L25_a3` 放大后 0.594 / 0.881 / 0.531 对扫描的 0.599 / 0.880 / 0.534（批大小 1 对 8 的 bfloat16 数值差，384 句里差 4 句的判定）。**诊断走的就是生产代码的路。**

环境事实（GPT §3 要求随诊断记录）：torch 2.13.0a0（NVIDIA 26.06 容器）、transformers 4.57.1、CUDA 13.3、模型 bfloat16、`Gemma3ForConditionalGeneration`、隐藏维 3840、48 层、滑动窗口 1024、层类型 40 层局部注意力 + 8 层全局、注意力实现 sdpa。强制真假提示下的 token 长度：估计集 68–117、测试集 65–121，**没有一条超过 1024**，局部注意力与本问题无关。

### 3.2 尺度事实：一个坐标占了残差流 99% 的能量

|---|---|---|---|---|---|---|---|---|
| 20 | 46 193 | 46 139（256） | 99.8% | **51.2%**（w₂₃₃₉ = −0.709） | 4.4% | **0.682** | 0.804 | 0.889 |
| 25 | 69 801 | 69 544（512） | 99.4% | 12.5%（w₂₃₃₉ = −0.342） | 0.4% | 0.880 | 0.859 | 0.889 |

Gemma-3-12B 的残差流在第 2339 维上有一个 4 到 7 万量级的"巨激活"（massive activation · 个别坐标比其余坐标大上千倍，是不少模型都有的现象），其余坐标中位数只有 18 到 50。均值差方向在第 20 层把一半的权重压在这一维上（真假两组在这一维的均值差被放大成了"方向"），结果是：① 这个方向读出的真假 AUROC 只有 0.682，比模型嘴上说的 0.889 差得远；② 沿它写入时，落在第 2339 维上的改动小于 bfloat16 在该量级的相邻间距 256，**30% 的改动在写回时被四舍五入丢掉**（kept/Δ = 0.70）。DAS 方向几乎不碰这一维（0.4% 到 4.4%），写入保留 98% 到 100%。GPT 猜的"写入被数值精度吞掉"**对均值差部分成立、对 DAS 不成立**，所以它不是 Gemma 上 DAS 失败的原因。

### 3.4 读法：断点在哪

1. **写入本身没问题。** 位置就是提示末 token（Gemma 聊天模板的换行符），零改动逐位复现，DAS 的改动 98% 到 100% 保留。GPT 的分叉 ①（位置或数值）对 DAS 排除。
2. **第 20 层：根本没有一条能交换首词的方向。** DAS 训练损失 4.70 已经说明没拟合上；训练对上只有 1.4% 交换成功。扫描选它只是调参集上的噪声（调参 ΔJ +0.047，测试 +0.009）。
3. **第 25 层：交换能泛化，放大却无益——GPT 的分叉 ③。** DAS 方向在没见过的 192 对上 80% 交换成功、关掉 87% 的 KL，把每句换成配对句的坐标后 J 从 +0.63 变成 −0.40——这条坐标**就是模型输出的决定变量**。但它读出的真假 AUROC（0.859）**不高于**模型嘴上的 0.889，放大它只是把模型已有的判断（包括错的）推得更极端：调参集上 6 句错→对、13 句对→错，ΔJ −0.036。
4. 合起来：**放大式要起效，坐标必须比模型的输出更懂真假**（Llama 第 11 层就是这种：方向能读出的比嘴上多，放大让下游"听"它）。Gemma 上我们找到的因果方向（晚层 DAS）不比输出多知道什么；更懂真假的读出（第 22 层探针 AUROC 0.95，第 4 轮）又不是一条能交换的单方向（中层 DAS 损失 3.6 到 5.0）。**Gemma 的失败不是估计器选错、不是强度、不是位置精度，是单条方向在 Gemma 上同时满足"因果"与"比输出更懂"两条的层不存在。** 对论文：消极；但它是一个可写的发现，且与 CDAS 的"可读 ≠ 可推"一致。

### 3.5 第一条追加线：秩（已出）

按上面的读法，先试**秩**：中层的真假信息可能分布在不止一个方向上，单方向换不动，低秩子空间或许能。`code/scripts/das_rank_pilot.sh`（服务器 09:44–10:40，GPU 3；`e1_directions.py` 新加 `--das-rank`）在 Gemma 第 18、20、22、24 层各训秩 4 与秩 16 的 DAS，其余设置与 tf 版完全相同（96 对、强制真假提示、提示末锚点、单种子、KL）。只看训练损失（`gemma3-12b/E1_summary_rank{4,16}.json`，`logs/das_rank_pilot_gemma3-12b.log`）：

| 层 | 秩 1（第 4 轮） | 秩 4 | 秩 16 | 子空间与均值差方向的最大主余弦（秩 16） |
|---|---|---|---|---|
| 18 | 4.44 | 4.28 | 4.13 | 0.67 |
| 20 | 4.70 | 4.22 | 3.91 | 0.70 |
| 22 | 3.58 | 2.63 | **1.50** | 0.73 |
| 23 | 1.18 | – | – | – |
| 24 | 0.79 | 0.20 | **0.07** | 0.63 |
| 25 | 0.039 | – | – | – |

读法：**秩只把"能交换"的前沿从第 23 层挪到第 22 层左右**（第 22 层 3.58 → 1.50，第 24 层 0.79 → 0.07），第 18、20 层 16 个维度仍然换不动（4.4 → 4.1、4.7 → 3.9，对应首词 KL 只关掉两三成）。**结论：在第 18–20 层，末 token 的残差里不存在任何能交换首词的低秩子空间**——不是"一条方向不够"，是信息不在那个位置。所以子空间放大评测没有必要跑（它要放大的坐标在那几层根本不控制输出），不再写它的 E23 路径。

### 3.6 第二条追加线：位置（在跑）

一个与数据吻合的机制假设：**Gemma 在第 23 层之前，真假证据不在末 token 上，而在陈述句自己的 token 上**。两条证据：① 第 4 轮全层 DAS 损失沿层的断崖恰在 22 → 23（3.58 → 1.18 → 0.79 → 0.039）；② Gemma-3-12B 的全局注意力层（能看整句的层，其余 40 层只看 1024 窗口内——本问题里窗口不是限制，但全局层与局部层的功能分工不同）在服务器配置里核实为第 5、11、17、23、29、35、41、47 层，**第 23 层正是第 4 个全局注意力层**。一个自然的解释是：末 token 在第 23 层的全局注意力里把证据从句子 token 上"拉"过来，之后它就是输出的决定变量；之前它还没拿到证据，所以在末 token 上怎么换都换不动。

检验（只改一个变量：写入位置）：`code/scripts/das_allpos_pilot.sh`（服务器 10:40–11:14，GPU 3）在第 18、20、22、23、24 层训 `--das-positions all` 的秩 1 DAS——把 base 序列**每个位置**在该方向上的坐标都换成 source 末 token 的坐标（CDAS 的一对多形式，`core/directions.py` 原有），其余设置不变，变体后缀 `tf-allpos`（`gemma3-12b/E1_summary_allpos.json`，`logs/das_allpos_pilot_gemma3-12b.log`）。

| 层 | 末 token 秩 1 | 末 token 秩 16 | **全位置 秩 1** | 全位置方向与末 token 均值差方向的余弦 |
|---|---|---|---|---|
| 18 | 4.44 | 4.13 | **0.126** | 0.04 |
| 20 | 4.70 | 3.91 | **0.142** | 0.00 |
| 22 | 3.58 | 1.50 | **0.188** | −0.03 |
| 23 | 1.18 | – | **0.154** | −0.02 |
| 24 | 0.79 | 0.07 | **0.113** | 0.00 |

**换得动了**：同样 96 对、同样秩 1，只是把写入位置从末 token 改成全部位置，第 18–22 层的损失从 4 以上掉到 0.13–0.19。假设成立的方向：**第 23 层之前，Gemma 的真假证据在句子 token 上，不在末 token 上**。这些全位置方向与末 token 的均值差方向正交（余弦 ≈ 0）——它们是 token 层面的另一种表示，不是末 token 那条方向。

两道必须过的检查（`diag_trace_direction.py --positions all`，GPU 0，11:14–11:25；输出 `gemma3-12b/trace_direction_allpos_L18_L20_L22_L23_L24.{md,json}`，日志同名）：① **反向也能换**——训练只做"假句 ← 真句"，要在全部 96 训练对与 192 调参对上同时看"真句 ← 假句"，否则学到的可能只是"全句往 True 推"的偏置；② **更懂**——这条方向在句子 token 上读出的真假（每句各位置投影的均值 / 最大值）AUROC 是否超过输出的 0.889。

**两道都没过。** 结果（调参 192 对；训练 96 对同样）：

|---|---|---|---|---|---|
| 18 | 50.7% | **0.982** | 0.332 | 0.53 / 0.45 | 0.72 |
| 20 | 50.7% | **0.974** | 0.420 | 0.51 / 0.45 | 0.52 |
| 22 | 51.8% | **0.974** | 0.457 | 0.55 / 0.51 | 0.61 |
| 23 | 51.1% | **0.982** | 0.409 | 0.52 / 0.55 | 0.69 |
| 24 | 52.8% | **0.961** | 0.369 | 0.52 / 0.55 | 0.54 |

逐句追踪说得更直白：每一层，沿全位置方向"交换"之后，**所有句子都答 True**（p_true 0.92–1.00）——假句换成真句的坐标答 True（训练要的），真句换成假句的坐标也答 True（本该答 False）。50% 的"成功率"恰是"假 ← 真"那一半。这条方向在句子 token 上不读真假（AUROC ≈ 0.5）。**全位置 DAS 学到的不是证据，是一条分布在全句上的"说 True"杠杆**——单向训练（只有假 ← 真）给了它这条捷径，正是 GPT 第 5 轮提醒的"把假句输出改得像真句并不叫纠错"。假设"证据在句子 token 上"因此**没有得到支持**（也没有被否定：我们只证明了单向目标找到的是捷径）。顺带：用末 token 中点做全位置放大，首词直接变成乱词（'pending' 之类），这个算子不能照搬。

### 3.7 第三条追加线：目标（在跑）

堵住这条捷径的办法就在 CDAS 的原始设计里：**双向目标**（`--das-bidir`，`core/directions.py` 原有）——除了"假句 ← 真句要答 True"，再加"真句 ← 假句要答 False"。一条纯"说 True"的方向过不了第二项；若中层句子 token 上真有可交换的证据，双向损失才能降下来。已起 `code/scripts/das_allpos_bidir_pilot.sh`（GPU 0，第 18、20、22、23、24 层，全位置 + 双向，其余不变，变体 `tf-bidir-allpos`），训完自动接同一份两道检查的诊断。这是 Gemma 上第三个单变量尝试（秩 → 位置 → 目标）；若双向损失仍降不下去，或降下去但读出仍 ≈ 0.5，Gemma 上"用一条方向放大证据"这条路就在我们能想到的变量上全部试尽，剩下的是换主张，那是赵磊的决定。
