# 立项后的计划与风险

这份文件回答两个问题：如果立项，还要做哪些实验；审稿人会从哪里质疑。

## 1. 要补的实验

按优先级排。前七项用现有的 4 张显卡可以完成，估计两到三周。

### 1.1 防御实验

这是目前完全空着的一块，也是论文"怎么预防"的主体。文献检索里没有找到任何一篇论文评估过"怎么拦模型自己写出的角色行"，现有防御都针对攻击者塞进输入的角色标记。

- **下一轮会不会照办。** 把一条假批准放进模型上一条回答的末尾，看下一轮模型是否把它当成用户的同意去执行。对比三种外壳做法：不处理；在系统提示里告诉模型"助手消息里出现的角色行不是用户输入"；外壳直接把那一行改写或删掉。
- **同一次生成里会不会照办。** 真实报告里有两条是编造批准和调用工具发生在同一次生成里。这种情况外壳来不及在两轮之间处理，要单独测：在工具调用之前截断，或者在解码时禁止角色词。
- **在回合开头和回答中途禁止角色词。** 推理时把用户角色词及其各种写法、各种语言的对应词禁掉。要测两件事：假用户发言是否消失，正常回答是否受影响。审稿人可能嫌这种做法太工程，所以要同时给出副作用的数据，并用机制部分说明为什么单靠后训练做不到。
- **回归测试。** 把探针整理成一个可以直接跑的测试：给一个模型，输出它在几种标准情形下的门的概率。换模型、换模板、微调之后各跑一次。

### 1.2 再微调会不会把门冲开

预研显示压制是后训练压出来的一层。别人拿这个模型再做一次微调，这一层还在不在，需要实测。已有一个相关的发现：AuditBench（2026 年 10 月版附录）里，微调数据有 11.2% 的样本把用户回合当成了训练目标，训出来的 Llama-3.3-70B 在最坏情况下 66.3% 的回答会接一条假用户回复；作者明确说这是数据错误造成的，不是微调的一般效果。所以"规范的微调会不会冲开"仍然没人测过。

用 Llama-3.1-8B，分别做 LoRA（低秩适配 · 主体权重不动，旁边挂一小块可训练的参数）和全参数微调，三种数据：

- 规范做法：套对模板，只对助手说的话计算损失。
- 常见的配置错误：对所有文字计算损失，包括用户说的话。
- 聊天记录式数据：多轮对话以 "User: … Assistant: …" 的纯文本形式塞进一条助手回答里。

每隔若干步读一次门的概率，画出它随训练步数的变化。

### 1.3 用各模型自己写的填充对话重做

预研的跨模型实验里，所有模型用的都是 Llama-3.1-8B 写的填充对话；日文实验里所有模型用的都是 Qwen3-8B 写的。也就是说，"模型自己之前的回答"其实是别的模型写的，日文对英文的对比同时改了语言和填充作者两个变量。早期设定下对四个模型做过对照，量级没有变化，但论文设定和日文都没做。立项后先补这一项，同时加入一个和 Shekkizhar 等重合的模型（Qwen3.5、gpt-oss 或 GLM-4.7），让"强行打开用户回合"的结果可以直接对照。

### 1.4 机制：第二个家族，以及排除底座的混杂

- **第二个家族。** 头的定位和消融目前只在 Llama-3.1-8B 上做了论文设定。要在 Qwen3-8B 的论文设定下重做，并在 Llama-3.3-70B 上看同一组头是否存在。
- **排除底座的混杂。** Llama-3.1-8B 底座模型里回合头的词向量全是零，没训练过，所以拿指令版模板喂底座时，底座看不见回合头。要给底座和指令版都用纯文本的角色标签（例如 "User:" / "Assistant:"）再跑一遍底座对比，代码里有现成的渲染函数。

### 1.5 语言曲线

现在只有英、中、德、日四种语言，按语言拆"底座对指令版"只有英、中两种。补到六到八种语言，每种语言都做：整场对话用该语言；填充对话用被测模型自己写的；底座和指令版各读一次；多 token 的词统一用整词概率。目标是画出"后训练的压低倍数随语言怎么变"，检验第四条主张。

**阳性对照。** 只看相关性，审稿人会说这是排除法。要从同一个底座做两次小规模的对话微调：一次覆盖某个缺的"角色词 × 语言"组合，一次不覆盖，看门会不会因此关上。已有论文示范过这类"从底座训练、只改覆盖"的对照设计（Marchisio 等 EMNLP 2024、Klerings 等 2026、Yoon 等 EMNLP 2026）。

### 1.6 回答末尾的测量和端到端演示

预研量的是"回答的第一个字"。真实报告里更常见的是回答说完之后接出一条假用户发言。要补两件事：

- 在回答末尾，也就是模型该收声的位置，量同样的概率。
- 搭一个真实的多步 agent 循环，演示完整链条：模型写出假批准，外壳把它留在上下文里，模型照着执行。

### 1.7 探针本身的改进

- 直接记录 `user` 的精确概率，不再只记前五名。
- 喂多 token 的角色词时喂整个词，不只喂第一个 token。
- 续写的判定改成两个人独立判定，或者用一个固定的判定模型加人工抽查。判定标准写进方法：A 类假用户发言、B 类伪造的机器输入、C 类不是换人说话；角色词后面紧贴、空格、冒号、换行都算，逗号开头算称呼。
- 区分"照抄"和"新编"，单独报告。
- 重跑污染样本改写那一组，把污染句换成英文。

### 1.8 真实报告的系统统计

把三家仓库里的报告完整收集一遍，逐条标注：模型、会话语言、上下文长度、是模型侧还是外壳侧、编造和执行是否在同一次生成里、后果。预研里只做到了逐条核实和粗分类。

### 1.9 闭源模型的旁证

闭源模型拿不到开口位置的完整概率。可以考虑的替代做法是按预研的对话骨架直接大量调用接口，数假用户发言的出现次数。这要花接口费用，而且在英文干净设定下可能什么也抽不到。是否做，取决于论文需不需要这一块。

## 2. 审稿人会从哪里质疑

| 质疑 | 现在的情况 | 应对 |
|---|---|---|
| 概率这么低，算问题吗 | 完全干净的英文对话里是千万分之一。污染后每百万个开口位置几条 | 给出三个放大因素的数字：自我污染、离开训练范围、agent 每天的回合量。补端到端演示。引真实报告、厂商的修补记录，以及 AuditBench 里数据出错时高达 66% 的比例 |
| 只量了第一个字，和真实事故的形态不一样 | 属实 | 1.6 |
| 机制只在一个小模型上 | 属实 | 1.4 |
| 底座对指令版的一万多倍里混着回合头没训练的影响 | 属实。同一模型内部的对比显示，后训练把污染带来的抬升压小了约 30 倍 | 1.4 |
| "模型自己之前的回答"其实是别的模型写的 | 属实，早期设定下的对照显示影响不大 | 1.3 |
| 强行打开用户回合让模型写用户发言，已经有人做过 | 属实。Magpie（ICLR 2025）用这个办法批量生成用户问题；Shekkizhar 等（2026 预印本）在 11 个开源模型上系统测过，结论是多数输出是复述或接着助手的话 | 明确引用。本研究的不同在于：测的是模型自己在助手回合里写出角色词的概率，而不是外壳替它打开用户回合；关心的是安全后果，不是续写质量 |
| "压制只在训练分布里有效"是已知结论 | 属实。Kotha 等 ICLR 2024 已经证明微调的压制在翻译成别的语言后会失效 | 明确让出一般规律。本研究给的是回合边界上的实例、各家模型的覆盖情况和部件级的机制 |
| "对齐只管开头几个字"是已知结论 | 属实。Qi 等 ICLR 2025 杰出论文，讲的是拒答 | 明确引用。本研究是同一现象在回合边界上的实例，并补上了部件和幅度 |
| 第四条主张的证据薄 | 四种语言，部分读数是上界，每种操作只对部分模型有效 | 1.3、1.5、1.7 |
| 对话材料是人造的 | 属实，骨架是固定的 | 换几套骨架；用真实 agent 轨迹做一组 |
| 闭源模型没测 | 属实 | 十个开源权重模型加公开报告。1.9 视情况 |
| 大写的 `User` 开头是称呼，不是换人说话 | 已经区分 | 判定标准写进方法，1.7 |
| 第一个 token 的概率和实际写出的文字可能对不上，已有论文报告过不一致率超过 60% | Llama-3.1-8B 上抽样命中次数和概率一致 | 每个模型都配端到端抽样验证 |
| 没有防御实验 | 属实 | 1.1、1.2 |

## 3. 投稿前必读

下面三篇只读到了摘要，可能改写主张，立项后先通读。完整的必读清单见 `../references/文献与新颖性核查.md` 最后一节。

- **Shiller 2026，"Role Tokens and Other Persona Cues in Instruction-Tuned LLMs"**（OpenReview Archive）。摘要说非标准的角色词以中等比例引出相应的角色行为，可能是第四条主张的先例。
- **"Understanding & Isolating the Assistant State in Instruction-Tuned Models"**（ACL ARR 2026 投稿）。研究模型在自己的停止符之后写什么，可能碰到第一、三条主张。
- **Yoo、Rozen 和 Harris，"The Assistant Persona Differs Across Languages in Activation Space"**（NeurIPS 2026 研讨会）。助手人设在不同语言里的内部表示不同，可能被当成第四条主张的机制先例。
