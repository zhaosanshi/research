# “幽灵用户”研究价值与提交建议

核验日期：2026-11-05。核验对象：[研究仓库固定版本 39bb6bc](https://github.com/zhaosanshi/research/tree/39bb6bcb17211bd0772e66a3f7af3b83e0b02f6e/Phantom_User)。本次结论以这一版本的代码和公开结果为准。

**判断：值得交给老师辅导，也值得继续做。现在是一份有真实问题、有效预研和明确缺口的立项材料，尚不是已经证明了核心安全主张的顶会论文。** 最值得争取的贡献是：模型怎样把自己写的文字误当成人的授权，这个错误怎样进入实际动作，以及如何在保留正常能力的情况下阻断它。

## 为什么有价值

**现实问题成立，而且证据比原材料写得更强。** [Claude Code #82619 的协作者回复](https://github.com/anthropics/claude-code/issues/82619#issuecomment-5310357746)将“助手生成假用户文字、紧接同次响应调用工具”称为正在跟踪的真实模型问题，并说明当时的跨轮修补不能覆盖同次生成中的工具调用。官方 [2.1.205 更新日志](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)也确有防止记录内伪造批准被采纳的补丁。这比单纯汇总几十条报障更能说明研究必要性。评论标注使用 AI 生成，身份来自 GitHub 协作者字段；它是厂商侧公开回应，不是独立实验复现，也不能据此推断当前所有版本仍然如此。

**问题的要害是授权来源。** 一个系统可能始终把消息标成“助手”，模型仍在同一次生成中把自己刚写出的“可以，发吧”当作继续行动的理由。因此，必须区分两种情况：外壳真的把文字重新解析成了用户消息；外壳没改消息角色，但模型在语义上把伪造内容当成同意。研究第二种情况尤其有现实意义，不能把全部事故归结为消息解析错误。

**预研不是空想。** 独立复算主表后，Llama-3.1-8B 两种内容中，插入污染的首词 `user` 概率分别升高约 **20.28 倍、40.44 倍**。26 条关键条件续写确实保存了假用户口吻的文字。注意力定位和重新前向执行的消融也确实在代码中实现，不能因后面的局限把这些进展一笔抹掉。

## 目前证据到底到了哪一步

| 主张 | 本次判断 |
|---|---|
| 已经出现角色污染的助手历史，会提高后来写出角色词的倾向 | 有直接对照和公开概率，主表复算一致 |
| 某种分阶段采样下，原装 Llama 能写出新的假用户发言 | 有文字证据；需明确完整采样规则，不能直接等同产品发生率 |
| 十个模型都能自然发生相同故障 | 尚未证明；跨模型多数是强制角色词后续写，而且文本性质有差异 |
| 少数注意力头参与该首词概率 | 有局部因果干预线索；逐头原始文件未公开，固定部件的跨任务泛化未验证 |
| 这些头是角色边界专属机制 | 尚未证明；已有普通词复制机制是强竞争解释 |
| 多语言差异由后训练覆盖缺口造成 | 有值得追的观察；语言、内容、填充作者同时变，因果归因还不成立 |
| 本实验已复现伪造批准并执行动作 | 尚未完成；目前是公开事故支撑动机，实验主要测角色文字 |
| 防御有效且不损害正常工作 | 尚未实验 |

“没有攻击者”是现实动机。当前污染实验则是研究者人为在历史中加入假用户行，模拟错误已经发生后的传播。这种设计合理，但应明确它研究传播条件，不能据此证明第一次自发故障的来源。

## 确认的错误与影响

详见 [代码与实验审核](audit_experiments.md)、[现实证据与第二视角审核](audit_reality.md)。下面按影响排列。

| 问题 | 已核实证据 | 影响与最小修正 |
|---|---|---|
| 首字抽样与完整生成未统一采样规则 | `e2e_sample.py` 手工首字抽样无前 k 名过滤，`generate` 未显式关闭该过滤；官方 4.57.0 配置流程可保留默认 50。10 个关键上下文的 `user` 排名全为 66–535 | 历史完整配置缺失，不能断言当时就是 50；但公开代码不能保证两段同分布。显式记录并统一规则，先小样本重跑。若采用前 50 名或累计概率 0.99，这些上下文中“首字恰为小写 user”的路径为零，**不等于所有位置、所有写法的故障为零** |
| 漏掉工具交接结束符 | `e2e_sample.py` 的停止集合漏 `<|eom_id|>`；70B 原始完整样本越过它继续写助手头，继而被标为假回合 | 应按模型的终止/交接协议结束当前生成并交还控制，不能把交接后强行续写计成自然事故 |
| 自动检测误报、漏报 | 实际执行检测函数：同一行 `Human: Yes...`、日文紧贴 `user` 会漏；正常引述和仅助手头会误报 | 自动字段只能找候选。正式事件率应依据带上下文的语义标签；现有人工复核的关键 A 类文本不因此作废 |
| 发生率合并权重不正确 | 各上下文最多续写 3 条，却用合并命中率乘合并 A 类比例 | 日常按命中数分层估计是 3.07/百万，用精确首词概率分层估计约 3.95/百万。两者估计方法不同，且续写样本很少；**不能把任一数字替换成精确产品发生率** |
| “假角色词位置”混入普通正文 | 代码干净格已被标出 4、1、8 个“假用户词”；日常干净格为零 | 用实际插入位置标注，别只认词面。日常污染示例的约 24% 注意力结果不受这项影响 |
| 批处理失败仍报成功 | 真实队列配无害失败替身运行：16 次失败后退出码仍为 0，并报完成 | 失败返回非零；重跑不要混用旧输出。当前公开数据未查到关键重复记录，不能说旧表已经被污染 |

另一个实验设计问题也已执行确认：结尾任务要求把条目移到 `Deployment` 段落后，提供的文件却没有该段落标题。正常追问缺失信息是正确行为。它不破坏“同一输入有无污染”的对照，但会削弱真实任务代表性；下一轮应给出完整可执行文件和正确答案对照。

## 创新性压力在哪里

最接近的论文经下载全文核查后，结论是：**已有研究占据了不少单独原理，尚有实证问题值得做；不能用“别人没做过完全相同的组合”替代贡献论证。** 全文文件和页码见 [独立文献审核](audit_novelty.md) 与 [主审全文阅读补充](全文阅读补充.md)。

- [Niu 等《Llama See, Llama Do》](https://arxiv.org/abs/2505.09338)已经研究上下文普通词的概率抬升、少量注意力头和消融。它也区分了这种机制与经典归纳头。因此，“发现几个复制头、它们不是归纳头”还不足以证明新的角色机制。需要普通词匹配对照，以及在新样本上检验预先选定的头。
- [AuditBench v4](https://arxiv.org/abs/2602.22755v4)已经报告训练数据错误导致假用户回合，并定位、修复。它的未额外微调模型在 4,000 次样本里没出现，不构成对百万分之几事件的反证：若发生率为 4/百万，4,000 次全零概率仍约 98.4%。本项目的机会在原装模型中的触发、传播与作用链，不能宣称学术文献从未记载假用户回合。
- [Ye 等论文作者的项目页](https://role-confusion.github.io/)已明确提出模型自己制造用户命令或批准的问题。因此，自造授权的想法本身也有公开先例，博客不等于同行评审，但仍应尊重其思想优先权。研究机会在可重复测量和因果证据。
- [Shekkizhar 等](https://arxiv.org/abs/2604.02315v2)已经系统测强制用户槽位的续写；其条件与本项目不同，但进一步压缩了“强制喂词后会写用户话”的独立创新空间。

原材料中一篇“待全文核验”的助手状态论文已找到正式发表版并通读；另两篇仍未取得可验证全文。本次不据其摘要下结论。因此，建议先不用“首次”作支柱，更不提供没有校准依据的“创新概率 70%”或录用概率。

## 推荐的动机与核心想法

**推荐动机：人类审批的可靠性，取决于系统能否分清“人真正说过什么”和“模型刚刚写出了什么”。** 当模型同时负责拟稿、描述交互记录和调用工具，虚构一句同意可能变成行动依据；这类风险不要求攻击者预先放置恶意输入。我们需要测量从自己生成的文字到未经授权动作的转化条件，而不仅是检测几种角色字符串。

可采用的工作题目：**《谁替用户点了头？智能体自造授权的形成、传播与阻断》**。这是供赵磊和老师选择的研究方向建议，不表示已证实了标题中的完整链条。

**推荐核心想法：把链条拆开测量，并验证哪些环节真的导致动作。** 分别记录：生成假用户内容、生成具体批准、模型把它当成同意、调用需要批准的工具、工具层是否放行。角色首词概率作为低成本诊断量保留，但必须检验它能否预测后面的行为，而不是默认它就是安全风险。

防御首先做简单、可核验的基线：工具放行只接受外壳记录的真实人类批准，并与具体动作对应；同次生成和后续轮次都在工具执行前检查。再比较文字拦截、系统提示、训练或内部干预。**这种来源校验原则已有相关工作，不能冒充新发明。** 论文贡献应是揭示具体失效条件、证明干预切断了哪一环，以及量出有效性与误拦代价。若只在一个明知会错的文本解析器上演示，贡献不够。

## 下一步只先做三件事

1. **修测量，再跑一个最小闭环。** 统一采样和停止规则，先检查 1–3 条原始输出；用正确且可执行的任务，在本地虚拟工具中记录“没有真实批准却调用/执行”。分别保留干净历史、人工污染历史、模型实际生成的污染历史；不得把人工污染的发生率叫自然发生率。同时测回答中途/末尾，避免只盯首字。
2. **区分新机制与普通抄词。** 在现有 Llama 上对角色词和同频普通词做匹配对照；头的名单在一组上下文选定，在另一组检验。对真实污染位置做替换与恢复，检查工具行动而不仅是 `user` 概率。先把一个模型讲透，再决定是否扩家族。
3. **做一个能解决问题的防御比较。** 对同次生成和跨轮传播分别测来源校验与简单文字规则；同时保留合法引述、写剧本、正常批准等样本，测任务完成和误拦。语言用相同内容的对齐版本。等闭环成立，再决定是否投入大规模多语言或微调实验。

如果第一步在合理的原装模型、正常解码下始终不能形成动作链，应据实收窄为“人工污染后的角色续写与传播机制”，或继续寻找已知事故对应的真实触发条件；不要为了保住标题无限扩大枚举。这个分叉正适合请老师指导。
