# 研究选题讨论：谁替用户点了头？

老师您好，我们希望请您帮助判断并收敛一个智能体可靠性与安全方向的选题。目前已经有一轮预研、代码和公开结果，希望以此讨论立项价值及最关键的验证实验。

**问题。** 模型有时会在自己的回答里写出一条并不存在的“用户发言”，甚至写成批准，然后依据它继续行动。Claude Code 的公开报告中已有同一次生成内出现假用户文字并调用工具的案例，项目协作者也回应其为已知模型问题，并说明当时的跨轮修补不能覆盖同次生成。我们关心的是：系统如何把模型生成的文字误认为人的授权，以及怎样阻断这一过程。[公开回应](https://github.com/anthropics/claude-code/issues/82619#issuecomment-5310357746)

**研究动机。** 人类审批能否成为可靠的控制手段，取决于系统能否确认批准确实来自人。如果模型可以自己写出批准并据此行动，单纯强调“重要操作先询问用户”仍可能失效。这种错误可能发生在消息角色没有被外壳改写的情况下，因此需要同时研究模型行为与工具执行边界。

**已有预研。** 我们用十个开源权重模型开展了不同范围的行为测试。完整机制分析主要在 Llama-3.1-8B 上进行。当前最可靠的结果是：在助手历史中人为插入三条假用户发言，后续助手回合首词写出 `user` 的原始概率，在代码与日常内容中分别提高约 20 倍、40 倍。已保存分阶段抽样下的假用户续写；跨模型强制角色词续写和多语言观察提示，角色词概率与实际续写身份必须共同判断。注意力归因与消融提供了末层少数部件参与的线索。

**当前证据边界。** 人工污染测的是错误传播条件，尚未复现完整的“首次自发伪造批准—误认授权—执行工具”链条。首词概率也还不是实际事故率。独立代码审核发现采样规则未统一、停止符处理及自动识别存在问题，正在据此明确修订范围；20–40 倍的原始概率对照已离线复算吻合。跨语言观察仍混有填充内容来源差异，角色复制也尚未排除一般抄词机制。

**相关工作与可争取的贡献。** 普通词复制及少数注意力头已有系统研究；AuditBench 已报告由特定训练数据错误制造的假用户回合；角色混淆论文作者也公开提出过模型自造批准的问题。我们不打算把现象、复制或授权来源校验的一般原则宣称为首次发现。希望争取的贡献是：在明确条件下复现与量化生成侧故障，验证从伪造文字到实际动作的因果路径，并评测能够切断该路径的防御。[复制机制研究](https://arxiv.org/abs/2505.09338)、[AuditBench v4](https://arxiv.org/abs/2602.22755v4)、[角色混淆项目页](https://role-confusion.github.io/)

**拟优先验证的三件事。** 第一，统一解码与停止规则，在正确可执行任务和虚拟工具里测完整动作链，区分干净、人工污染与模型生成污染。第二，用角色词与普通词的匹配对照、预先固定的部件名单和新任务检验，区分一般复制与角色授权失效。第三，比较提示、文字拦截与真实批准来源校验，在同次生成及跨轮场景中同时测越权动作和正常任务误拦。

**希望您重点指导。** 以“模型自造授权导致控制失效”为主线，是否有足够独立的研究贡献；最应该先做哪一个因果实验；机制分析与系统防御各应做到什么深度，才能形成聚焦、可信的顶会论文。
